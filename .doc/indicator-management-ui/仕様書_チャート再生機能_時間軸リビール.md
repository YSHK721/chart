### 1.1 最優先命題

本機能の最優先命題は **「戦略立案のための事前分析・検証」** である（取引結果の再生・分析検証は副次目的）。
過去の任意時刻 t を「その時点で実際に知り得た情報だけ」で再現し、「この指標を根拠にここでエントリーしたら妥当か」という戦略仮説を **ルックアヘッド（将来リーク）なしに検証** できるツールとする。

## 3. 設計の中核 ＝ ルックアヘッド排除（look-ahead-free 因果再現）

各フレーム t は **t 時点で知り得た情報のみ** を表示する。

- **足**: `candles[:t+1]`（クライアント側スライス・即時）。
- **インジケーター**: `df[:t+1]` で都度再計算し、**ライブ更新と完全に同一条件**（同一 compute 経路・`_TGP_SEED=20260101` 固定・同一 `maxbars` 窓・同一 params）で算出する。
- **禁止**: 間引き（throttle）／全系列1回計算→tスライス／TGP省略 等の近似は一切不可。
- **保証**: 「再生フレーム t ＝ ライブで“現在”が t だった時に出る帯」と完全一致（決定性保証）。この因果忠実性が戦略仮説検証の妥当性を担保する。

### 3.1 再計算 mode（確定）

| 操作 | mode | 理由 |
|---|---|---|
| 前進1コマ（連続再生・次へ） | `latest` | ライブが実際に使う増分経路と同一コードパス＝最厳密 |
| 後退・スクラブ・分析アクション | `full` | 窓が縮む/任意ジャンプのため窓全体を全再計算 |

両者は seed固定・同一窓で値一致（§11 で実証）。

## 4. 機能仕様

### 4.0 土台: 因果リビール再生

再生バーで現在フレーム t を制御し、足とインジを t に同期させる。連続再生（play/pause＋速度=fps上限）＋ステップ（1足前/次）＋スクラブ（スライダー）＋ライブ復帰。

#### 4.0.0 表示・操作の追加仕様（確定・プロトタイプ 260626-01 で反映）

1. **チャート高 100%**: 再生バー／リードアウトを除く残り全高をチャートに割り当てる（縦フレックス＋autoSize）。
2. **時間足選択**: 既存 timeframe（1m〜1M）を再生対象に選択可能。切替で当該時間足の足・インジ（および再生フレーム）を再構成（既存 `setTimeframe` 経路に相乗り）。
3. **最新足の右側に余白**: 直近足の右に余白（`rightOffset` 相当のバー数）を設ける。追従表示では可視レンジ右端を t より offset 本ぶん外側に取る。

##### 実装上の必須知見（リビール描画の堅牢化・プロトタイプで検出）
リビールを「t時点まで `setData(slice)`」で実装すると**毎フレーム系列長が変化**し、可視レンジ操作と競合して lightweight-charts 内部が非同期に `Value is null` を投げ描画が固着する。**未来足を whitespace（`{time}` のみ・OHLC無し）にして系列長を一定に保つ**こと（lwc 定石）。同様に可視レンジ適用は `requestAnimationFrame` で再レイアウト後に行う。本番 `ChartRenderer.setCandles` 経路もこの方式に合わせる。

#### 4.0.1 表示窓の追従（確定・プロトタイプ §11.3 で検出）

再生中は時間軸を **現在フレーム t 周辺の直近 N 本に追従ズーム** する（既定）。理由: 帯は直近 maxbars 窓のため、`fitContent` で全リビール履歴を映すと t が進むほど帯（＝判断対象のアクティブ窓）が視覚的に潰れ、戦略分析の対象域が縮む（§11.3 の t1300 スクショで実証）。
- 既定 = **再生追従**（t を右端付近に保ち、可視範囲を t-（N-α）〜t+α に設定。N は maxbars を内包する値、例 maxbars×1.5）。
- トグルで **リビール全体表示**（`fitContent` 相当）に切替可能。
- 実装: `replay_controller` が各フレームで `chart.timeScale().setVisibleRange({from, to})` を呼ぶ（追従モード時）。lwc 呼び出しは ChartRenderer 隔離を保つ。

### 4.A 決定点リードアウト

一時停止/ステップ時、t 時点の **OHLC＋表示中全インジケーターの値** を一覧パネルに表示。「自分のエントリー規則がこの t で発火するか」をその場で評価できる。値は各インジ系列の t 時点の点から取得（前進=latest の末尾点／pause=full の該当点）。既存 crosshair readout を拡張。

### 4.B リペイント検証

任意の t で「as-seen-at-t の帯（`untilTime=t`・full）」と「最終確定の帯（`untilTime` なし・full）」を比較し、将来情報による過去値の描き直し（リペイント）の有無・大きさを可視化＋数値化（`repaintDelta` が絶対値＋相対％）。`profit_band` global はリペイント有、robust は非リペイント、`tgp_btlm` は窓スライドで過去値が変化（§11 実証: 約0.5%ドリフト）。その指標を戦略根拠に使って良いか判定できる。

**トレーリング窓指標の比較モデル（プロトタイプ 260626-01 で精緻化）**: `tgp_btlm` 等は「最終確定帯」が**直近 maxbars 本しか覆わない**ため、過去座標では as-seen-at-t と比較する相手（最終帯）が存在しない。よってリペイント検証は「重なり区間（最終帯が覆う範囲）での乖離」を測るか、または「as-seen-at-t vs as-seen-at-(t+k)」を重なり座標で比較する。重なりが無い座標では「比較対象なし（後の t で比較可）」と明示する。全長計算型（profit_band global）は全座標で最終帯と比較可能。

### 4.C 候補点マーク＋先送り観察

再生中に現在 t を「候補エントリー」として印付け（時刻・価格・その時点のインジ値スナップショット）。先へ進めてその後の価格・帯推移（結果）を観察。先送り観察も **現在フレームまで** しか見せない（因果一貫）。マークはチャート上のマーカー＋一覧パネルに表示し、`forwardOutcome`（Δ価格・経過足・最大順行/逆行）を読み取り表示。

## 5. アーキテクチャ（新規モジュールと境界）

クリーンアーキ準拠。純ロジック（DOM/lwc/timer/fetch 非依存・node:test 対象）と DOM/lwc 配線を分離。

### 5.1 新設（純ロジック・usecase）

- **`web/js/usecase/timeline_player.js`**: 再生状態機械。`frameIndex`/`playing`/`fpsCap`/`bounds`、`indexForTime`/`timeForIndex`（二分探索・往復一致）、`clampIndex`、`stepNext/stepPrev`、`delayMs(fpsCap)`、`visibleRangeFor(frameIndex, candles, N)`（再生追従の {from,to} 算出・純関数・§4.0.1）。タイマー非保持。throttle 判定を持たない（毎フレーム再計算が絶対条件）。
- **`web/js/usecase/replay_analysis.js`**: 分析純関数群。`readoutAt(seriesByInstance, candle_t)`（能力A）/ `repaintDelta(asSeenSeries, finalSeries)`（能力B）/ `forwardOutcome(mark, candlesUpToCurrent)`（能力C・現在フレームまで限定）。

### 5.2 新設（DOM/lwc 配線・adapter/front）

- **`web/js/adapter/front/replay_controller.js`**: 非同期 run-loop（直列リビール）、LiveUpdater 一時停止/復帰、再生バー＋リードアウト＋マークUI の DOM 配線（`indicator_controller.bind` と同形）。timer/delay/document は注入。リペイント比較用の比較系列は replay 側で専用 lwc ライン系列を生成/破棄し、既存 `indicator_controller` の系列に触れない。

### 5.3 既存への最小配線

- `web/js/adapter/front/compute_http_client.js`: `untilTime` を reqBody へ素通し（`mode` と同パターン・未定義時は載せない＝後方互換）。
- `web/js/adapter/front/indicator_controller.js`: `setUntilTime(t)` 追加＋`_gatewayAdapter().compute` に `untilTime` 注入（timeframe/limit と同じ注入点・全 recompute 経路へ自動伝播）。描画系列スナップショット取得手段を1つ公開（読み取り専用）。
- `web/js/adapter/front/composition_root_front.js`: B方式時のみ組み立て、controller/renderer/liveUpdater/最新candles 参照を注入。時間足切替（`setTimeframeObserver`）に再生状態リセットを相乗り。
- `web/index.html` / `web/css/app.css`: ツールバー直下に `#replay-bar`＋リードアウト/マーク一覧パネル。既存トーン流用・非破壊。
- `web/build.mjs` `MODULE_ORDER`: 新3モジュールを登録（未登録は A方式バンドルが実行時クラッシュ・`build_module_order.test.js` が回帰検出）。

## 6. バックエンド仕様（最小・後方互換・新mode不要）

### 6.1 `api/adapter/compute/dataset.py` — `truncate_until`

```
truncate_until(df, until_unix) -> df:
  index(time) を _to_unix_seconds で秒化し until_unix 以下の行のみ返す（含む・原 df 非破壊）。
  空/範囲外を安全処理。load_candles と同一換算で境界厳密一致（決定性の根拠）。
```

### 6.2 `api/adapter/controller/compute_controller.py` — `untilTime` 差込

`df = dataset.load_dataframe(...)` の **直後・`limit` tail の前** に挿入:

```
until = body.get("untilTime")
if isinstance(until, int) and not isinstance(until, bool):
    df = dataset.truncate_until(df, until)
```

- 処理順序: **untilTime → limit → tail（mode=latest の min_window 含む）**。切断後 df に既存ロジックが効くため時間軸が candles と一致。
- `untilTime` 省略時は df 無変更＝既存テスト完全緑（後方互換）。型不正（str/負値/bool）は無視。

### 6.3 `/candles`

無改修（足リビールはクライアント slice、リペイント比較は `/compute` を2回呼ぶ）。

## 7. 既存ライブ更新との整合

- 再生突入で `liveUpdater.stop()`（冪等）。両者とも `controller.isRecomputing()` を尊重し二重 compute しない。
- ライブ復帰: `playing=false` → 比較系列/REPLAY状態クリア → `renderer.setCandles(allCandles)`（全足）→ `setUntilTime(undefined)` → `recomputeAllApplied({mode:'full'})`（present復元）→ `liveUpdater.start()`。

## 8. 非機能仕様

| 項目 | 仕様・実測（§11） |
|---|---|
| 因果性 | 各 t で帯 last ≤ untilTime（将来リーク無し）を保証。 |
| 決定性 | seed固定で同一 untilTime 2回が series 完全一致。 |

### 11.1 サイクル1（ライブラリ層・OLS／TGP）

| 検証 | 結果 |
|---|---|

### 11.3 サイクル3（ブラウザUI・実TGP×HTTP・playwright スクショ）

最小再生UI（再生バー＋チャート＋リードアウト）を worktree web/ に置きサーバ配信、playwright で複数フレームを撮影。

| 検証 | 結果 |
|---|---|
| 足リビール | t150=2022序盤のみ／t1300=2022→2026全履歴。右端が常に t・将来足非表示（視覚的に確認）。 |
| 帯スライド | tgp帯（紫mean＋点線q）が右端~100本窓に張り付きスライド。 |
| 決定点リードアウト（能力A） | OHLC＋帯値＋「close vs mean → buy候補/見送り」を t 時点表示。 |
| 実レイテンシ | ブラウザ→HTTP→実TGP 各フレーム196–227ms・2fps再生。 |
| **検出UX問題** | 大きい t で `fitContent` が全履歴を映し、直近100本の帯が極小化。→ §4.0.1「再生追従」を仕様化。 |

### 11.4 確定した設計事実

1. `untilTime` は body 1パラメータ・`df.tail` 前で切断するだけで、実インジ計算（tgp/MCMC含む）を無改変で因果化できる。
2. 帯は常に n=maxbars（=100）。右端に張り付く窓がスライドする見え方（履歴全体に帯は引かれない）。
3. standard で実 ≈5fps。プランの「直列await＋fps上限＋generation破棄」で吸収。
4. 再生中の表示は再生追従が必須（§4.0.1）。`fitContent` 固定は分析域を縮める。

## 12. 検証手順（E2E）

- `cd indigators/indicator_ui && ./serve.sh` 起動 → `tgp_btlm` 適用 → 再生突入。
- ▶ で足が左→右へ増え、各フレームで帯が `df[:t+1]` 窓に追従。⏸/◀▶ステップ・スクラブ・速度切替を確認。
- 因果性/決定性: 特定 t にスクラブした帯と、ライブで同じ t を最新足として計算した帯が一致。将来足が表示に影響しない。
- 能力A: 一時停止で全インジ値＋OHLC がパネルに出る。
- 能力B: `profit_band global` でリペイント有・`robust` で無が可視化/数値化。
- 能力C: 候補点マーク後に先送りして Δ価格・経過足が現在フレームまでで更新。
- ライブ復帰で全足＋60秒ポーリング再開。`node --test`（web）と Python テスト全緑、untilTime 省略時の既存挙動が不変。

## 13. 用語

| 用語 | 定義 |
|---|---|
| リビール型再生 | 現在時刻 t 以前の足・インジのみ表示し、t を進めて足を増やす（バックテスト再生）。 |
| ルックアヘッド排除 | 各フレームが t 時点で知り得た情報のみを表示すること（将来リーク無し）。 |
| リペイント | 将来データ到来により過去座標の指標値が描き直されること。トレーリング窓型指標で発生。 |
| as-seen-at-t | 時刻 t 時点で実際に表示されていた指標値（`untilTime=t` で再計算した値）。 |
| untilTime | `/compute` に追加する切断時刻（UNIX秒）。df を当該時刻まで切断する。 |
| fps上限 | 連続再生のフレーム間最小ディレイ。計算間引きではなく描画レート上限。 |
