## 4. 換算モデル

### 4.1 換算プリミティブ（唯一の定義）

```
bars(tf, P) = 半開ローリング窓 [t − P, t) に含まれる実バー本数の中央値
              （右端 t は実バー時刻のみを走査。窓の左端が実測期間の外に出る t は除外）
```

- `tf`：時間足（`1m`…`1M` の 9 足）
- `P`：暦期間（1 時間 / 4 時間 / 1 日 / 1 週間 / 1 ヶ月 / 3 ヶ月 / 6 ヶ月 / 1 年 / 2 年 / 3 年 / 5 年）
- 暦の月・年は `pandas.DateOffset(months=…/years=…)` の暦規約に従う（30 日・365 日の固定秒数換算はしない）
- **中央値を採る理由**：窓に含まれる本数は右端の位置（曜日・月末・祝日の並び）に依存して分布を持つ。代表値として外れ値に頑健な中央値を採り、単一の決定論的な整数へ落とす。

この 1 つの定義から、プリセット値（§4.3）と期間表記入力の換算値（§6.3）の**両方**を導出する。別定義を置かない。

**表の読み方（例）**

- 日足の「1年 = 258」：過去 1 年に日足が 258 本実在する（＝ 258 営業日）。
- 1 時間足の「1週間 = 115」：過去 1 週間に 1 時間足が 115 本実在する（5 営業日 × 23 本／日）。
- 4 時間足の「1日 = 6」だが「1週間 = 31」（5 × 6 = 30 ではない）：4 時間バケットは UTC 境界で切られるため、セッション境界をまたぐバケットが週に 1 本生じる。実測値をそのまま採用する（D-2）。

### 4.4 表の凍結と版管理

E-9 のとおり実測値は計測時点のセッション構造に依存する。表が黙って変わると、**保存済み指標の値と、それを選んだときのラベルが将来ずれる**。これを防ぐため次を規定する。

1. 表は**静的定数**として front に置く。実行時の再計測・サーバ問い合わせは行わない。
2. 表には**版（`v1`）・計測日・実測期間・データソース**をコード上のコメントとして併記する。
3. 表の更新は**明示的な版上げ**でのみ行う（`v2` を追加し `v1` は削除しない）。既に保存済みのパラメータ値は本数として保存されているため、版上げによって**遡って変化しない**。
4. 銘柄追加時は `datasetRef` をキーとする表を追加する。表の構造は `{ datasetRef: { tf: { unit: bars } } }` とし、現状は `jp225_tick` の 1 件のみを定義する。未登録 `datasetRef` はプリセット機能を無効化する（F-P3）。

**再計測の再現性（v0.1.1 追記・実測）**：同一データに対する計測は決定論的だが、**データが伸びると一部セルが ±1 変動する**。右端サンプルを等間隔で取るため、バーが増えると格子が動き、窓に入る本数分布の中央値が 1 だけずれることがある（実測：`serve.sh` のデータ watch 稼働下で 40 分後に 30m の `1mo` が 971→972）。これは誤りではなく「暦期間に入る本数」が本来持つゆらぎであり、**表を実行時に計算せず版で凍結する判断の根拠そのもの**である。版上げの判断は ±1 の揺れではなく、§4.5 検証 1 が示すセッション構造の**段差**（例：1h が 22→23 本/日）を根拠に行う。

## 6. 機能仕様

### 6.1 UC-P01 プリセットの提示

- 提示先：期間フラグを持つパラメータの入力欄。
- 提示集合の決定（決定論的・この順で適用）：
  1. §4.3 の表から、**実効計算時間足**（§6.5）の行を引く。
  2. 本数が **2 以上 1500 以下**の単位のみを候補とする。
     - 下限 2：本数 1 は「期間の指定」として意味を持たないため（1 時間足の「1時間」等）。
     - 上限 1500：チャートが保持するバーの上限（E-11）。これを超える値は実在しないバーを指す。
  3. 当該パラメータの `min` / `max` 制約を満たさない候補を除く（例：`min: 3` のパラメータに本数 2 の候補は出さない）。
  4. 残った候補を**期間の短い順**に並べ、**先頭 5 件**を採る。
- 結果（表・`min`/`max` 制約なしの場合）：

| tf | 提示されるプリセット |
|---|---|
| 1m | 1時間(60) / 4時間(237) / 1日(1281) |
| 5m | 1時間(12) / 4時間(48) / 1日(266) / 1週間(1329) |
| 15m | 1時間(4) / 4時間(16) / 1日(89) / 1週間(445) |
| 30m | 1時間(2) / 4時間(8) / 1日(45) / 1週間(225) / 1ヶ月(971) |
| 1h | 4時間(4) / 1日(23) / 1週間(115) / 1ヶ月(496) / 3ヶ月(1480) |
| 4h | 1日(6) / 1週間(31) / 1ヶ月(134) / 3ヶ月(401) / 6ヶ月(798) |
| 1D | 1週間(5) / 1ヶ月(21) / 3ヶ月(65) / 6ヶ月(129) / 1年(258) |
| 1W | 1ヶ月(4) / 3ヶ月(13) / 6ヶ月(26) / 1年(52) / 2年(104) |
| 1M | 3ヶ月(3) / 6ヶ月(6) / 1年(12) / 2年(24) / 3年(36) |

- 表記規則（D-4）は **`本数（期間名）`**＝本数を主・期間を従とする。一覧では 2 列（期間名／本数）に展開し（§7.2）、1 行に収める文脈（ツールチップ・確認表示）では `115（1週間）` の形で書く。期間表記入力を換算した場合は入力された記法を括弧に入れる（`5d` → `115（5日）`）。
- 候補が 0 件のとき（`min`/`max` 制約が厳しい・未登録 `datasetRef` 等）はプリセット UI 自体を出さない（従来どおりの数値入力のみ）。

### 6.2 UC-P02 プリセットの選択

- 手順：一覧から 1 件を選ぶ → 当該パラメータの値を選択された本数へ**代入**する → 既存の検証（`validateForm`）と条件付き有効化／表示の再評価を通常どおり実行する。
- 代入後は通常のパラメータ値であり、**プリセット由来であることは保持しない**（保存もしない）。理由：保持すると換算表の版上げ時に保存値と表示ラベルが乖離しうる（§4.4-3）。
- OK 押下までは確定しない（既存のダイアログ挙動を変えない）。

### 6.3 UC-P03 期間表記の直接入力（FR-P03）

- **文法**（大文字小文字を区別する `M`／`m` に注意）：

  | 記法 | 意味 | 例 |
  |---|---|---|
  | `N`（単位なし） | 本数そのもの（従来どおり） | `50` → 50 |
  | `Nmin` | N 分 | `30min` |
  | `Nh` | N 時間 | `4h` |
  | `Nd` | N 営業日 | `5d` |
  | `Nw` | N 週 | `2w` |
  | `NM` / `Nmo` | N ヶ月 | `3M` / `3mo` |
  | `Ny` | N 年 | `1y` |
  | 日本語表記 | 上記に同じ | `5日` / `2週間` / `3ヶ月` / `1年` |

  - `N` は正の整数または小数（`0.5d` 等）。空白は前後・単位前ともに許容し無視する。
  - `5D` / `5 d` / `５ｄ`（全角）も受理する（大文字小文字・全半角を正規化する。ただし `M`＝月／`m`＝分の区別は正規化後も保持する）。

- **換算規則**（決定論的・この順で適用）：
  1. §4.3 の表に `(実効時間足, N×単位)` の直接エントリがある場合、**その実測値**を用いる（例：1 時間足の `3M` → 表の「3ヶ月」＝ 1480）。
  2. 直接エントリがない場合、**基本単位の N 倍**とする（例：1 時間足の `2M` → 2 × 496 = 992／`5d` → 5 × 23 = 115）。基本単位は `min`→1分・`h`→1時間・`d`→1日・`w`→1週間・`M`→1ヶ月・`y`→1年。
  3. `min` 単位は名目換算（`N` 分 ÷ 時間足の分数）とする。セッション内で分足・時間足に欠落がないことを実測で確認済み（表の「1時間」行が名目値と一致：1m=60・5m=12・15m=4・30m=2・1h=1）。
  4. 結果を四捨五入して整数化する。
  5. 当該パラメータの `min` / `max` 制約を満たさない場合は**代入せず**エラー表示とする（黙って丸めない・F-P1）。
- 入力欄が期間表記を保持できるよう、期間フラグ付きパラメータのコントロールは `number` から**期間入力コントロール**（新 `control_type`）へ切り替える（E-4・§8.1）。
- **確定タイミング**：入力欄からフォーカスが外れた時点、または Enter 押下時に換算し、入力欄の表示を**換算後の本数**へ置き換える（`5d` と打つと `115` になる）。
- 換算不能な文字列（`abc` / 単位のみ / N が 0 以下）はエラー表示とし、直前の有効値を保持する（F-P1）。

### 6.4 時間足切替時の挙動

- **パラメータ値は変換しない**（E-2 の現行挙動を維持する）。プリセットは入力補助であり、確定後の値は通常のパラメータである。
- 変わるのは**提示されるプリセット集合**のみ（§6.1 で実効足の行を引き直す）。
- 理由：値を自動変換すると、ユーザーが明示的に入力した値を UI が書き換えることになる。これはビュー・状態への自動介入を明示イベント起点に限る既定方針（ISSUE-164 の裁定）と同じ性質の問題を、パラメータ領域で作る。

### 6.5 実効計算時間足（FR-P04）

プリセットの基準となる時間足は、次の優先順で解決する（E-3）。

1. 当該指標が計算時間足 override パラメータ（`timeframe`）を持ち、その値が `chart` 以外である場合 → **その値**。
2. それ以外 → **チャートの現在の時間足**。

これは既存の `TimeframeController.effectiveTimeframe(tfParam)` と同一の解決規則であり、規則を二重に定義しない（当該メソッド、またはそれと同値の純関数へ委譲する）。

ダイアログ内で `timeframe` パラメータを変更した場合、同一ダイアログ内の他パラメータのプリセット集合を**即座に引き直す**（既存の `onChange` → 再評価の経路に乗せる）。

### 6.6 失敗定義（基本設計書 §7.2.1 の F 系へ加法）

| ID | 失敗 | 検出方法 | システム挙動 |
|---|---|---|---|
| F-P1 | 期間表記が解釈不能／換算値が `min`・`max` 制約に反する | 入力確定時のパース・制約評価 | 代入せず当該行にインライン表示。直前の有効値を保持。OK は既存の検証規則に従う |
| F-P2 | 換算表に当該時間足の行がない（将来足の追加時） | 表の引き当て失敗 | プリセット UI を出さない。数値入力は従来どおり機能する（機能の欠落であって障害ではない） |
| F-P3 | 換算表に当該 `datasetRef` の表がない（銘柄追加時） | 表の引き当て失敗 | F-P2 と同一挙動 |
| F-P4 | 換算値が `RECENT_BARS`（1500）を超える | §6.1-2 の上限判定／§6.3 の換算後判定 | プリセットは提示しない。期間表記入力の場合は代入せず「チャートが保持する本数を超える」旨をインライン表示 |

## 7. UI 設計

### 7.1 配置

期間フラグ付きパラメータの行を、数値入力の右に**プリセットボタン**を持つ形へ変更する。

```
 期間            [ 115        ] ⏱   本
                 └ 数値/期間表記入力  └ プリセット
```

- 行の構造（ラベル／コントロール／単位／エラー）は既存のまま（`properties_dialog.js` の `_buildFieldRow` を変更しない）。プリセットボタンはコントロール要素の内部に含める（新 `control_type` の生成器が組み立てる）。
- 単位表示（`unit.bars` →「本」）は既存経路をそのまま使う。

### 7.2 プリセット一覧

ボタン押下でポップを開く（時間足メニュー・`timeframe_menu.js` と同型の開閉挙動：トリガークリックでトグル・項目選択で閉じる・外側クリックで閉じる）。

```
[⏱]
 ├ 4時間        4
 ├ 1日         23
 ├ 1週間      115
 ├ 1ヶ月      496
 └ 3ヶ月     1480
```

- 各行は `期間名` と `本数` の 2 列。現在値と一致する行は選択状態（`is-active`）で示す。
- 一覧の見出しに基準時間足を出す（例：`1時間足 基準`）。実効足が override で変わる指標において、何を基準にした値かを画面上で判別可能にする。

### 7.3 入力欄の振る舞い

- 通常時：本数（整数）を表示する。
- 入力中：`5d` 等の文字列をそのまま表示する（E-4 のため `type="text"` ベースとし、`inputmode="numeric"` は付けない）。
- 確定時（blur / Enter）：換算して本数表示へ置き換える。
- 期間表記が使えることをユーザーへ示すため、`placeholder` または `title` に例（`50 / 5d / 3M`）を出す。

### 7.4 モード間の一貫性

ライブ／リプレイで同一 UI・同一文言・同一換算表とする（E-7 の symlink 単一ソース共有により、共有ベースへの実装で自動的に成立する）。

## 11. 付録：実測の再現手順

換算表は次の手続きで再導出できる（§4.1 の定義そのもの）。

1. `data/marketdata/rollups/jp225_tick/jp225_tick_{tf}.csv` を読む（`1m` のみ `data/marketdata/jp225_tick_m1.csv`）。`date` 列は `datetime64[us]` であるため、秒への変換は `astype("datetime64[s]").astype("int64")` を用いる（`astype("int64") // 10**9` は**誤り**＝マイクロ秒を秒として扱ってしまう）。
2. §4.2 の実測期間で右端 `t` を等間隔サンプリングする（最大 4000 点）。
3. 各 `t` について左端 `t − P` を `pandas.DateOffset` で求め、`searchsorted` で `[t−P, t)` に入る本数を数える。窓の左端が実測期間の始端より前になるサンプルは除外する。
4. 本数の中央値を整数として採る。
5. 検証 1（年別 1 セッション日あたり本数）と検証 3（休場日の内訳）は `marketdata.session_day.session_day_starts` / `session_date_label` で日切りしてから集計する（日切り規約の再実装は禁止）。

計測スクリプトは実装時に `indigators/indicator_ui/tools/` 配下へ収める（換算表の版上げ時に同一手順で再計測できるようにするため）。本設計時点の計測は 2026-07-28 に実施したものであり、§4.3・§4.5 の値はその出力である。

### 12.2 実装で判明した事実

1. **新規 usecase モジュールは replay_ui の symlink が必要**（§8.1 是正）。E-7 の「replay_ui 側の変更は不要」は既存共有ファイルについての記述であり、新規追加分には当てはまらない。symlink がないとリプレイ側で 404 になる。
2. **`timeframe_menu.js` を MODULE_ORDER の前方へ移す必要があった**。時間足ラベルの単一情報源（`timeframeLabels`）を `properties_dialog` が参照するため。当該モジュールは相対 import を持たない葉なので前方移動で依存順は壊れない。
3. **換算表の再計測は ±1 揺れる**（§4.4 追記）。凍結方針の妥当性を裏づける実測。
4. **`Value is null`（lightweight-charts）は本実装と無関係**。期間プリセット UI に一切触れない対照実行（指標追加 → 時間足切替のみ）でも同じく発生する既知事象であり（ISSUE-167／2026-07-27 の再観測記録）、本実装の経路（`_onGear` 内のダイアログ生成）は対照実行では実行されない。新規 Issue は起票しない。
