# モード定義一覧（indicator_ui）

- **目的**: リポジトリ内で「モード」と呼ばれる概念の定義・値・判定条件を単一ドキュメントに集約し、実装・レビュー時の参照点とする。
- **出典**: 全定義は実コード確認済み（2026-07-17 時点・参照先は各節に明記）。
- **更新規則**: モードの追加・値の変更・撤去を行う変更では本書を同一コミットで更新する。

---

## 1. 動作方式（A方式 / B方式）

| 項目 | A方式 | B方式（推奨） |
|---|---|---|
| 内部値 | `mode: 'a'` | `mode: 'b'` |
| 配信 | `file://` 単一 HTML（`out/prototype.html`・`node build.mjs` 生成） | served `http://`（`framework/server.py`・`serve.sh`） |
| 計算 | 埋め込み事前計算（EmbeddedComputeGateway） | ライブ API（ComputeHttpClient → `/compute`） |
| params 反映 | **variant のみ**（他 params は描画へ未反映＝ダイアログのパラメータタブに A方式注記を表示） | 全パラメータを実再計算・実反映（注記非表示） |
| ローソク | SAMPLE_DATA | `GET /candles`（full CSV と時間軸一致） |
| スタイル/可視性タブ | **両方式で実反映**（applyOptions 直接反映のため方式非依存・ISSUE-109） | 同左 |

- **判定**: フロントの `location.protocol`（`http/https` → B方式、`file:` → A方式）で自動切替。
- **参照**: `indigators/indicator_ui/README.md`（A方式と B方式の違い）／`properties_dialog.js`（A_METHOD_NOTE）。

## 2. ライブ追従モード（FOLLOW / ANALYSIS）

| 値 | 定義 |
|---|---|
| FOLLOW（ボタン点灯） | ライブ更新 ON＋新足で右端追従 |
| ANALYSIS（消灯） | ライブ更新停止＋背景 tint で状態明示 |

- **遷移**: **ライブボタン（`#live-follow-toggle`）のクリックのみ**（ISSUE-118 ユーザー裁定 2026-07-18）。過去へスクロールしてもモード・背景は変わらない。再 FOLLOW クリック時は無条件で最新足へ catch-up スクロール。
- **旧仕様（削除済み）**: 右端離脱で自動 ANALYSIS／右端復帰で自動 FOLLOW（EPS=1 バー・programmatic scroll 抑制付き）は ISSUE-118 で削除。
- **参照**: `web/index.html`（live-follow-toggle）／`adapter/front/live_follow_controller.js`。

## 3. 計算モード（full / latest）

| 値 | 定義 |
|---|---|
| `'full'`（既定） | `renderer.remove` ＋ `_draw` の全系列再描画（params 変更による系列改名に追随） |
| `'latest'` | 末尾K点のみ `updateSeriesTail` で差分反映（過去確定足は不変・全再描画しない） |

- **制約**: `latest` は全系列が line/histogram の指標のみ（`_defCanTailUpdate`）。horizontal_line を含む・混在指標は full を強制（trim 済みデータでの全描画によるライン潰れ回避）。`forceTail=true`（reveal seam）は例外的に末尾差分へ倒す。
- **参照**: `adapter/front/indicator_controller.js` `recomputeInstance` / `_computeInstance` / `_defCanTailUpdate`。

## 4. MP 表示モード（market_profile `mode`）

| 値 | 定義 |
|---|---|
| `'normal'`（既定） | 通常プロファイル表示 |
| `'sessions'` | セッション別表示 |
| ~~`'replay'`~~ | **撤去済み**（ISSUE-082）。保存済み `mode='replay'` は復元時に `'normal'` へ正規化 |

- **直交性（Model A 統一成長モデル）**: 表示モード（normal/sessions）と成長状態（growing/static）は直交。GrowthCoordinator が FOLLOW→`growing=true`／ANALYSIS→`growing=false` の単一信号へ写像し、`actor.applyGrowthState({growing})` で適用する。旧方式（FOLLOW 時に実効モードを `'ticklive'` へ置換）は廃止済み＝`resolve` は `'ticklive'` を返さない。
- **後方互換**: `mode` 欠落時は legacy キーから導出（`sessions:true`→`'sessions'`・`replay:true`→`'normal'`・両 OFF→`'normal'`・キー無し→null＝actor 既定）。
- **参照**: `adapter/front/market_profile_params.js` `deriveMpMode`／`adapter/front/mp_live_mode_coordinator.js`（GrowthCoordinator）。

## 5. MP 解像度モード（market_profile `resmode`）

| 値 | 定義 |
|---|---|
| `'bins'`（client 既定） | ビン数（`bins` param）で解像度を決定 |
| `'range'` | 保存したレンジを維持し client が `&barw=` を送出して解像度を決定 |

- **後方互換**: `resmode` 欠落時は `range` がレンジ数値集合→`'range'`、`range='auto'`→`'bins'`、両方無し→null（client 既定＝bins）。
- **制約**: tf-period（日別列描画）では resmode/bins/range は無効（GRID_W 固定）＝ダイアログでグレーアウト（ISSUE-070）。
- **参照**: `adapter/front/market_profile_params.js` `deriveMpResmode`。

## 6. リプレイモード（チャート再生・時間軸リビール）— replay_ui 専用

- **定義**: 過去の任意時刻 t を「その時点で実際に知り得た情報だけ」で因果的（look-ahead-free）に再現する再生機能。最優先命題は**戦略立案のための事前分析・検証**（取引結果の再生は副次目的）。
- **所在**: 独立アプリ **replay_ui**（`simulator/replay_ui/`・`serve.sh` で起動する「リプレイ（因果リビール再生）UI」）。**indicator_ui（present）からは ISSUE-082 で撤去済み**（replayBar・スワイプスクラブは present に存在しない。保存済み MP `mode='replay'` は `'normal'` へ正規化）。
- **機構**: 各フレーム t で足をクライアント側 `candles[:t+1]` に切断し、インジはサーバ側 `df[:t+1]` で再計算（`/compute` に `untilTime` を付与＝ライブと同一条件）。前進＝計算モード `latest`／後退・スクラブ・分析＝`full`。再生中は LiveUpdater 停止。実体は TimelinePlayer（再生状態）／ReplayController（運転・配線）／replay_view（lwc 隔離点）／replay_boundary_dim（境界減光）。
- **MP 表示モードの差分（indicator_ui との違い）**: replay_ui の MP は **4 値排他** `'normal' | 'replay' | 'sessions' | 'ticklive'`（`market_profile_actor._applyMode` が排他を構造的に保証・未知値は `'normal'`）。`'replay'`＝下部スライダバー（scrub）＋T 縦線＋トリム＋スナップショット。`'ticklive'`＝tick 逐次成長。indicator_ui 側は §4 のとおり 2 値（normal/sessions）＋成長軸へ移行済み。
- **参照**: `.doc/indicator-management-ui/仕様書_チャート再生機能_時間軸リビール.md`／`simulator/replay_ui/serve.sh`／`simulator/replay_ui/web/js/adapter/front/market_profile_actor.js` `_applyMode`／`market_profile_replay_bar.js`。

## 7. シミュレーション — 「モード」ではなくサブシステム

- **定義**: リポジトリに「シミュレーションモード」という UI 切替状態は**存在しない**。存在するのは **simulator サブシステム**（`simulator/`）＝「MT5 忠実バックテストシミュレータ」。JP225 の EA 戦略を MT5 Strategy Tester と **trade-by-trade で一致（reconciliation）** するよう再現するバックテスト実行基盤であり、UI モードではない。
- **構成**: クリーンアーキテクチャ（`domain ← usecase ← adapter ← main`）。usecase に RunBacktest / RunIsOos / WalkForward / Optimize 等。付属 UI は replay_ui（§6）と report_ui（バックテストレポート）。
- **チャート UI との接点**: バックテストの取引履歴はトレードマーカー（`trade_markers_renderer.js`・indicator_ui / replay_ui 両方）としてチャートへ描画される。
- **参照**: `simulator/README.md`／`.doc/sim-report-ui/`。
