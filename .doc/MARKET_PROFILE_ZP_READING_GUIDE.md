## 0. 用語定義

| 用語 | 定義 |
|---|---|
| **占有 / 滞在 `N_obs(p)`** | 対象期間に価格帯 `p` に居た時間（分単位）。実際に観測された量。 |
| **Null B** | 「その日にありえたはずの値動き」を人工的に多数生成した**帰無モデル**。下記 §2。 |
| **基準（平均）`Ê_NullB[N(p)]`** | Null B のサロゲートを多数生成したときの、価格帯 `p` の滞在時間の**平均**。 |
| **ばらつき `ŝd_NullB[N(p)]`** | 同じサロゲート集合における滞在時間の**標準偏差**。 |
| **超過占有 `z(p)`** | `(N_obs(p) − 基準の平均) / 基準の標準偏差`。単位は「σ 何個ぶん」。 |
| **`tpo`（応答フィールド）** | 上記 `z(p)` の値（`src=zp` のとき。名前は他 src との共通スキーマに由来）。 |
| **`norm`（応答フィールド）** | 描画するバーの長さ（0〜1）。定義は `clip(z, 0) / z_max_disp`。 |
| **`z_max_disp`** | 表示ビンにおける `clip(z,0)` の最大値。これが満尺（`norm = 1.0`）になる。 |
| **`z_max`（応答フィールド）** | **表示ビンではなく細格子（fine grid）での最大 z**。POC\* の算出に使う。`norm` の分母**ではない**（実測: `z_max = 16.11` に対し表示ビン最大は 11.44 で、`norm` は後者で 1.0 になる）。 |
| **`to`** | リプレイ／ライブの単一時計。この時刻までのデータだけで集計する（因果・未来非参照）。 |

## 1. 何を表しているのか（結論）

`src=zp` のバーの長さは **「その価格帯に長く居たか」ではなく「偶然の値動きでは説明できないほど
長く居たか」** を表す。

- ただ長く居ただけの価格帯（＝相場が普通に通過しただけ）は、基準も同じくらい大きくなるので
  `z` は伸びない。
- 同じ滞在時間でも、「その時間帯の荒れ方から見て居るはずのない場所」に居れば `z` は大きくなる。

したがって `zp` は **出来高分布ではなく異常検出**である。POC（`poc`）も「最も長く居た価格」では
なく「最も `z` が高い価格」を指す（`poc_star` が z 基準の峰）。

---

## 2. 基準（Null B）は何の平均か

**「ありえたはずの 1 日」を人工的に何千通りも作り、その価格帯に何分居たかを平均したもの。**

生成手順（`null_b_kernel.surrogate_logprice_chunk`）:

1. 当日から遡る**直近 `NULL_HIST_DAYS = 250` 日**の完了日を材料にする（未来日は使わない＝因果）。
   材料が `NULL_MIN_DAYS = 60` 日未満なら `z` は未定義（None）。
2. 1 日を「分」に割り、各分をその**時間帯（ブラケット）**に属させる。
3. 分ごとに、**同じ時間帯の 1 分の変化率（log 差）を、ランダムに選んだ別の日から借りてくる**。
4. 借りた変化率を**当日の始値から順に掛け合わせて**、偽の 1 日分の値動きを作る。
5. これを **`M_REPS_DAY = 2000`（完了日）／`M_REPS_LIVE = 1000`（当日・部分日）** 通り生成し、
   価格帯ごとの滞在分数の**平均**と**標準偏差**を取る。

この作り方が保つもの／壊すものが `zp` の意味を決めている:

| | 内容 |
|---|---|
| **保つ** | 時間帯ごとの動きの荒さ（寄り付きは荒い・昼は静か 等）。当日の始値。 |
| **壊す** | その日固有の「この価格に居座った」という水準の構造。 |

だから `z` は「時間帯ごとのボラティリティで説明できる範囲を超えた居座り」を検出する。

## 3. 表示規則（実測で確認・2026-08-09）

対象: `to=1786054500`・666 ビンの実応答。

| 規則 | 実測 |
|---|---|
| **バーが出る条件は `z > 0`** | バーあり 547 本の `z` は **0.01〜11.44**／バーなし 119 本は **−1.85〜0.00** |
| 境目はちょうど `z = 0` | `z=0.00` → 長さ 0、`z=0.01` → 長さ 0.0013 |
| 長さは `z` に比例 | `norm = clip(z,0) / z_max_disp`。**表示ビンの最大 z**（この応答では 11.44）が満尺。応答の `z_max`（16.11）は細格子の最大値で、分母ではない |

**よくある誤解**: 「ばらつき（σ）を超えたものだけ出る（`z > 1`）」ではない。閾値は **基準の平均**で
あって σ ではない。σ は**長さの物差し**（何 σ ぶん上回ったか）として効く。

- `z > 0`：基準の平均より長く居た → バーが出る
- `z ≤ 0`：基準の平均以下 → バーは出ない（長さ 0）

## 4. 確定したバーが更新される理由（設計どおり・不具合ではない）

MP は「バーごとに確定して積み上がる系列」**ではない**。`to` 時点で**全期間を集計し直した
プロファイル 1 枚**である。加えて `zp` は基準で標準化した相対値なので、新しいティックが
入ると基準側も動き、**過去の価格帯の値まで変わりうる**。

### 実測による裏付け（`to` を 10 分進めて突き合わせ）

| 観測 | 値 |
|---|---|
| 変化したビン | 666 中 **7 本のみ**（いずれも直近 10 分に値動きがあった 65531〜65610 の帯） |
| 変化の向き | **増減の両方**（65531.65: 1.17 → 1.11／65551.30: 0.57 → 0.52／65570.95: 0.87 → 1.04） |
| 不変だったもの | POC・POC\*・VA 上下・価格レンジ・ビン数・`z_max` |

**「減った」ことが標準化の決定的証拠**である。累積の滞在時間なら時間が進んで増えることは
あっても減ることは絶対にない。減るには「その価格帯の滞在」より「基準」の方が大きく増える
必要がある＝基準で割っている。

値動きの無かった 659 ビンが 1 つも変わっていないのは、基準の変化が効くのが**直近に滞在が
入った近傍だけ**だからである（全体を一律に割り直す形の正規化ではない）。

### 未来参照ではない

基準の材料は**当日から遡る完了日のみ**、観測は `to` までで打ち切る（`market_profile_zp` の
`col_hi` 打ち切り）。したがって過去バーの値が動くことは「未来を見た」ことを意味しない。
`to` 時点で知りうる情報だけで計算し直した結果である（as-seen-at-`t`）。

## 5. 運用上の含意

1. **リプレイ再生中、MP は毎ティック計算し直される**。当日・部分日は `M_REPS_LIVE = 1000` 通りの
   サロゲートを都度生成するため、他の指標より重い（実測 1 回 0.30 秒・ISSUE-301 是正後）。
2. **過去の列を不変にしたい場合**は `zp` のままでは実現できない。「期間ごとに閉じた
   プロファイル（tf-period 列）」へ切り替える**仕様変更**になる（未起票）。
3. **他の `src` との違い**: `src=dwell` は素の占有量である。実測（同じ `to` 2 点・666 ビン）では
   **増減とも 0 ビン**で、`zp` のような過去の塗り替えは観測されなかった。
   「過去が動かないこと」を優先するならこちらが候補になる（ただし「偶然では説明できない
   居座り」の検出力は失われる）。
   **未検証**: `dwell` が `to` をどの粒度で反映するか（10 分進めても 1 ビンも動かなかったため、
   確定足単位でしか進まない可能性がある）。採用を検討する際は先に実測すること。
