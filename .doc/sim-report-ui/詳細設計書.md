### 4.2 導出ロジック（一意確定・derive.py）

#### 4.2.1 sl/tp 導出（致命-1・EA固定SL/TP 実証）

`stop_entry_probe.py:83-102` の `_calc_sltp`：基準価格 `price` から `SL = price ∓ dist`、`TP = price ± dist`、`dist = points × point_size`（`stops_level × point_size` を下限クランプ）。
ペンディング約定は `fill_pending_order` で **注文価格に約定（スリッページ0）**＝`tr.entry_price == 注文price`。よって SL/TP は **entry_price から決定論的に再構成可能**：

```python
def derive_sl_tp(side, entry_price, *, sl_points, tp_points, stops_level, point_size, digits):
    min_dist = stops_level * point_size
    def fmt(p): return f"{round(p, digits):.{digits}f}"
    sl = tp = ""
    if sl_points > 0:
        d = max(sl_points * point_size, min_dist)
        sl = fmt(entry_price - d) if side == "buy" else fmt(entry_price + d)
    if tp_points > 0:
        d = max(tp_points * point_size, min_dist)
        tp = fmt(entry_price + d) if side == "buy" else fmt(entry_price - d)
    return sl, tp
```
- StopEntryProbe_EA は `SL=200pts`/`TP=500pts`/`stops_level=0`/`point_size=0.1`/`digits=1`（`reconcile_is.py:108-125` 実証）＝固定。
- **point_size はハードコード禁止**：`spec.point_size`（SymbolSpec 由来）と EA param（sl_points/tp_points）を CLI から UC へ注入（§7）。
- **代替策（EA が固定SL/TPでない将来戦略の場合）**：UC は EA param を契約に持つため、固定でなければ `derive_sl_tp` を呼ばず空文字とし、契約に「sl/tp は当該EAで供給不能」と注記する分岐を持つ（YAGNI: 現対象 StopEntryProbe は固定のため本分岐は未活性・設計上の保険）。本対象では固定が実証済のため一意確定。

#### 4.2.2 order/id（致命-2）

`order = id = i + 1`。明細・マーカー(`renderMarkers` の `'e'+id`/`'x'+id`)・scatter(`{x,y,id}`)・balance連動・heat/graph フィルタが全て同一 id 空間を共有。BacktestResult.trades の配列順は決済確定順で決定論（`run_backtest.py` 全決済経路が `trades.append` を順次実行）。

#### 4.2.3 mfe/mae（bars 走査・point_size 由来）

試作 `prep_data.py:72-84` の `excursion` を移植（UTC・point_size 乗算）：
```python
def excursion(bars, bar_times, side, ep, t0, t1, point_size):
    lo = bisect_left(bar_times, t0); hi = bisect_right(bar_times, t1)
    if hi <= lo: return 0.0, 0.0
    seg = bars[lo:hi]; hh = max(b.high for b in seg); ll = min(b.low for b in seg)
    if side == "buy": mfe_pts = max(0.0, hh - ep); mae_pts = max(0.0, ep - ll)
    else:             mfe_pts = max(0.0, ep - ll); mae_pts = max(0.0, hh - ep)
    # 試作の POINT_VALUE_JPY=0.1 は point_size と同値。SymbolSpec.point_size を使い JPY 換算（ハードコード排除）。
    return round(mfe_pts * point_size, 2), round(mae_pts * point_size, 2)
```
> 試作の `POINT_VALUE_JPY=0.1` が偶然 point_size と同値だが、本番は `spec.point_size` を一次とする（TBD-04 解消・point=0.1 のハードコードを排除）。

#### 4.2.5 走行 balance・balance_curve（致命-3）

`run_backtest.py:111-151` の `_close_open_trade` は `trades.append(trade)` と `balance_curve.append(account.balance)` を **同一メソッド内で必ずペア実行**（reverse/sl/tp/stop_out/end_of_test の全決済経路・bar-mode/every-tick 両経路）。例外で片方のみ append される経路は無い。よって：
- `trades[i].balance = balance_curve[i]`（1:1・致命-1の走行残高）。
- `agg.balance_curve = [{"time": _unix(trades[i].exit_time), "value": balance_curve[i]} for i in range(N)]`（致命-3：`list[float]`→`[{time,value}]`）。
- **成立条件**（every-tick 経路含む）：`len(trades) == len(balance_curve)` かつ各 i で 1:1。**結合テスト `test_export_oracle.py` で `len(trades)==len(balance_curve)` と `balance_curve[-1]==MT5_FINAL` を固定**（§8.2）。
- 初期証拠金 10,000 起点・累積は engine の `account.balance` が既に保持（試作 `summarize`/`balance_curve` 準拠。UC側で再累積する必要なし＝SSOT は engine の balance_curve）。

### 4.3 時刻正規化（`_unix`）

```python
import pandas as pd
def _unix(t) -> int: return int(pd.Timestamp(t).timestamp())  # epoch int はそのまま、datetime64 は秒へ
```

- pandas は composition（adapter/tools）に閉じる。UC（usecase）へは int 化済の値を渡し usecase→domain のみ依存を保つ（main の `_bar_period` と同方針）。

### 5.5 null/inf 規約（JSON.parse 失敗防止・致命の派生対策）

- **方針**：`json.dump(payload, f, allow_nan=False, ...)` を採用（NaN/Infinity を出力しない＝ブラウザ `JSON.parse` 互換）。
- Presenter は dict 化の最終段で **inf/-inf/nan → null** に正規化する純関数 `_sanitize(obj)` を再帰適用：
  ```python
  import math
  def _sanitize(o):
      if isinstance(o, float):
          return None if (math.isinf(o) or math.isnan(o)) else o
      if isinstance(o, dict):  return {k: _sanitize(v) for k, v in o.items()}
      if isinstance(o, list):  return [_sanitize(v) for v in o]
      return o
  ```
- 対象：`summary.profit_factor`/`payoff`（gl=0 / avg_loss=0 で inf）、`degradation.*.ratio`（既に is==0 で null）。front は `isFinite(v)` ガード済（試作 `cfmt`:1032 実証）で null/非有限を "—" 表示。
- 区切りは試作同様 `separators=(",", ":")`（最小化）＋ `ensure_ascii=False`（日本語 reasons/label 保持）。
