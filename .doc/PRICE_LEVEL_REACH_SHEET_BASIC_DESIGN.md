# 価格水準到達シート 基本設計書 v0.1.0

- 起票: 2026-08-28（ISSUE-449）
- 状態: **設計確定（実装未着手）**
- 依頼者裁定: 到達時刻は定義 A（現在の到達が始まった時刻）で確定（2026-08-28 承認）

---

## 1. 目的

各時間足の**価格が、指標のどの水準に到達しているか**を 1 枚で直感的に把握する。

非目的（明示的に対象外）:

- 成績・エッジの評価（Sharpe・勝率・期待値）。本シートは現在状態の表示のみを行う。
- パラメータ最適化グリッド（パラメータ × パラメータ）。設計途中で検討したが破棄した（§9）。
- 指標の計算式・描画の変更。本シートは既存の計算結果を**読むだけ**である。

---

## 2. 用語定義（本書で固定する）

| 語 | 定義 |
|---|---|
| **水準** | 価格スケール上の 1 本の線。指標インスタンス（indicatorId ＋ params）が出力する価格系列 1 本を指す。 |
| **到達** | 現在価格がその水準を跨いだ状態。判定は固定値比較ではなく `price_t` と `level_t` の**交差**（水準自体がバーごとに動くため）。 |
| **到達時刻** | **定義 A**: 現在の到達状態が始まった時刻。価格が水準を離れた時点でリセットされる。窓内の最古の到達（定義 B）は採らない。 |
| **chart 追従水準** | params の `timeframe` が `"chart"`（未指定含む）の水準。表示時間足ごとに値が異なる。 |
| **MTF 固定水準** | params の `timeframe` が `1D` / `1W` / `1M` 等で明示された水準。**表示時間足に依らず値が同一**。 |
| **足内更新** | ティックごとの更新。`/live_ticks` の tails 経路。 |
| **バー確定更新** | 足が閉じるたびの更新。`/compute` 経路。 |

## 3. 対象（実測に基づく確定列挙）

対象は「各時間足で実際に設定している指標」に限る。入力はチャートテンプレートの export
（`indicatorUi.templates.v1` / `indicatorUi.templateBindings.v1`）であり、カタログ全指標ではない。

### 3.1 採用する指標（価格スケール＝価格が到達しうる水準を出す）

| indicatorId | 水準系列 | 足内更新 | 延べ本数 |
|---|---|---|---|
| `moving_averages` | `MA`（`Smoothing`/`Upper`/`Lower` は現行設定では未出力） | 可 | 57 |
| `btlm_trail` | `btlm_trail_mean` / `btlm_trail_q{pct}` | 可 | 8 |
| `cvfe` | `cvfe_u1` / `cvfe_u2` / `cvfe_l1` / `cvfe_l2`（価格スケール上のバンド） | **不可** | 8 |

### 3.2 対象外と理由

| indicatorId | 理由 |
|---|---|
| `ma_marod` / `btlm_trail_marod` / `profit_rsi` | 別 pane のオシレータ。価格スケール上に無く「価格が到達」が定義できない |
| `tickvol` | tick 数。価格から導かれる量ですらない |
| `market_profile` | 価格分布そのもの。水準の概念が別（POC・VA）。追加要否は未裁定（§8） |
| `price_range_power` | 価格軸分布（`archetype = axis_distribution`）。同上。4h に 1 本のみ |

### 3.3 時間足と紐付け

`1m`→tpl#4 / `5m`→tpl#5 / `15m`→tpl#6 / `1h`→tpl#7 / `4h`→tpl#3 / `1D`→tpl#9 / `1W`→tpl#8 / `1M`→tpl#4。

- `1m` と `1M` が同一テンプレート `tpl#4` を共有するのは**正しい設定**（依頼者確認済み 2026-08-28）。
- `tpl#2`（名前 "D"）は未紐付け。**未確認事項**（§8）。

## 4. 表構造

### 4.1 行と列

- **行** = 一意な水準（indicatorId ＋ params）。指標名では固定しない。
- **列** = 表示時間足 8 列（`1m` `5m` `15m` `1h` `4h` `1D` `1W` `1M`）＋ **MTF 共通 1 列**。
- **行の並び** = 水準の現在値の**価格降順**。
- **現在値行** = 独立行として価格順の位置に挿入し、左端に実数値を置く。

### 4.2 MTF 固定水準を 1 列へ畳む根拠（実測）

| 群 | 水準の種類 | 延べセル |
|---|---|---|
| chart 追従 | 26 種 | 40 |
| MTF 固定 | 12 種 | 33 |

MTF 固定水準は表示時間足に依らず値が同一であるため、時間足列に展開すると**同じ数字が最大 3 列に重複**する
（例: `1D/5/hlc3` は 5m・15m・1h の 3 版面に出現するが値は 1 つ）。1 列へ畳むことで総セルは **73 → 52**。

行を指標名で固定してはならない根拠: `moving_averages` は全時間足通算 27 種あるのに各時間足は 6〜9 種しか
持たない。指標名を行に固定すると表の約 7 割が空欄になる。

### 4.3 セルの内容

各セルは以下を同時に持つ。

1. **水準の実数値**（桁は銘柄仕様の `digits` に従う。シート側で桁を決めない＝ISSUE-368）
2. **到達状態の配色**（未到達／到達済み）
3. **到達時刻**（到達済みセルのみ。定義 A）

## 5. 到達判定と到達時刻の導出

### 5.1 判定（交差）

水準はバーごとに動くため、固定値との比較では判定できない。バー系列 `t` に対し

```
reached_t := (price_t >= level_t)      # 上側水準は方向を反転
```

現在の到達状態は最新点の `reached` である。

### 5.2 到達時刻（定義 A）

現在の到達状態が始まった時刻 = **`reached` が現在と同値である連続区間の始端の時刻**。

```
first_t := min{ s | reached_s = reached_now  かつ  ∀u∈[s, now] : reached_u = reached_now }
```

価格が水準を離れて戻ると、戻った時点が新しい `first_t` になる。

### 5.3 クライアント側で積み上げてはならない（根本要件）

到達時刻をフロントで観測しながら積み上げると、**シートを開いた時刻に依存**し、開き直すたびに値が変わる。
これは表示の欠陥であり、選択肢ではない。到達時刻は必ず**水準系列と価格系列の履歴の突合**から導出する。
履歴は既存 `full_compute`（`adapter/compute/latest_dispatch.py:27-31`）が返す全件系列で足りる。
新規の統計・新規の保存領域は不要。

## 6. 更新経路（2 段）

| 段 | 契機 | 経路 | 内容 |
|---|---|---|---|
| 1 | バー確定 | `/compute`（全件系列） | 水準系列と価格系列を突合し、全セルの水準値と到達時刻を再導出する |
| 2 | ティック | `/live_ticks` の tails | 現在価格を更新し、到達状態と行の並び（価格降順）だけを更新する |

段 2 の対象は足内更新を宣言済みの指標に限る。`cvfe` は増分器が無いため段 1 のみで更新される
（`adapter/compute/live_tick_tails.py` が `None` を返し、ティック更新から明示的に落ちる）。
これを隠さず、`cvfe` 行には更新粒度がバー確定であることを表示する。

費用: 既存記録の実測は 0.5〜0.86 ms/tick/インスタンス（ISSUE-257）。段 2 の対象は 52 セルより少ないため
納期上の懸念は小さいが、**着手前に現行コードで再実測する**（記録値をそのまま設計根拠にしない）。

## 7. 設計方針（SOLID 写像）

- **OCP**: 既存の compute・指標定義・チャート UI を改変しない。シートは既存の計算結果を読む追加の購読者。
- **単一ソース**: セルの計算式を写さない。水準＝既存系列、到達＝既存系列同士の比較。計算の第 2 定義を作らない。
- **DIP**: 交差判定・到達時刻導出・行の並び替えは純関数（DOM・HTTP・localStorage 非依存）。
- **ISP**: 既存の TailSpec 契約（`instanceId` / `indicatorId` / `variant` / `params`）をそのまま使い、広げない。

## 9. 破棄した案と理由

| 案 | 破棄理由 |
|---|---|
| パラメータ × パラメータのグリッド 65 枚 | 時間足を軸に置かないと「各時間足が」を比較できない。目的に対して構造が合わない |
| 分位水準に限定した 5 指標のシート | 「分位水準」は依頼者の用語誤りで、真の要件は「価格が到達した水準」。価格スケール指標が対象になる |
| 足内更新できない指標をバー確定更新で同一に扱い「リアルタイム」と称する | 症状回避の応急処置。更新粒度が違うことを隠さず表示する（§6） |
