## 1. 目的

各時間足で、**現在値が指標のどの水準に到達しているか**を直感的に把握する。表は 2 枚に分かれる。

| 表 | 何が到達するか | 縦の並び |
|---|---|---|
| **第 1 表: 価格ラダー** | 価格が、価格スケール上の水準に到達 | 価格降順の 1 本の軸（全指標・全時間足が価格という共通軸を持つ） |
| **第 2 表: オシレータ水準到達表** | 指標値が、自分の分位のどこに居るか（連続量 `p`・§5.3） | 指標ごと（単位が異なり共通軸を持たない） |

2 表を分ける根拠: オシレータは指標ごとに単位が違い（% 乖離・RSI・tick 数）、第 1 表の価格順の並びに
混ぜられない。混ぜると 1 枚の中に読み方が 2 通り生じる。

**2 表を橋渡しする経路が 1 本だけある**（v0.5.0・§5.5）。オシレータの分位水準を**価格へ投影**し、
第 1 表の**価格セルの背景**として塗る。行は増えない（分位は行ではなく**区間の境界**である）。
読み方は 1 つに固定される: **この価格で引けたら、各地平の `p` はどこになるか**（`p` は §5.3）。

非目的（明示的に対象外）:

- 成績・エッジの評価（Sharpe・勝率・期待値）。本シートは現在状態の表示のみを行う。
- パラメータ最適化グリッド（パラメータ × パラメータ）。設計途中で検討したが破棄した（§10）。
- 指標の計算式・描画の変更。本シートは既存の計算結果を**読むだけ**である。

## 2. 用語定義（本書で固定する）

| 語 | 定義 |
|---|---|
| **水準** | 指標インスタンス（indicatorId ＋ params）が出力する水準系列 1 本。第 1 表では価格スケール上の線、第 2 表では指標自身の分位水準を指す。 |
| **観測値** | 水準と突き合わせる量。第 1 表では**価格**、第 2 表では**指標値**（% 乖離 / RSI / tick 数）。 |

| **到達時刻** | **定義 A**: 現在の到達状態が始まった時刻。観測値が水準を離れた時点でリセットされる。窓内の最古の到達（定義 B）は採らない。 |
| **chart 追従水準** | params の `timeframe` が `"chart"`（未指定含む）の水準。表示時間足ごとに値が異なる。 |
| **MTF 固定水準** | params の `timeframe` が `1D` / `1W` / `1M` 等で明示された水準。**表示時間足に依らず値が同一**。 |
| **足内更新** | ティックごとの更新。`/live_ticks` の tails 経路。 |
| **バー確定更新** | 足が閉じるたびの更新。`/compute` 経路。 |

## 4. 第 1 表 = 価格ラダー（v0.4.0 で確定）

### 4.1 形

**価格を唯一の軸**にする。全時間足の価格水準を 1 本の価格軸へ投影し、価格降順に並べる。
時間足は軸ではなく**各行の属性**（バッジ）になる。

- **行** = 水準 1 本（指標インスタンス × 系列）。**束ねない**（依頼者裁定 2026-08-29）。
- **列** = 距離 / 価格 / 時間足 / 水準ラベル の 4 列。時間足の列は持たない。
- **並び** = 価格降順。現在値は独立行として価格順の位置に入る。
- **各行** = 現在値からの距離、水準の実数値、**直前行との価格差**、時間足、一意なラベル。

実測（2026-08-29・ライブ計算サーバ・JP225）: **価格水準 88 本**（現在値 65,756.0 で上 44 / 下 44）。

束ねない根拠（依頼者裁定）: 束ねると大枠の水準しか把握できない。実測上の損失も無い
（§4.4 のとおり帯幅を変えても「次のターゲット」の持続は伸びない）。重なりは
**直前行との価格差**を各行に添えて読み取れるようにする。

### 4.2 なぜ時間足を列にしてはならないか（実測）

価格は全時間足で**同じ 1 点**である。一方、水準の値は 88 個あり、すべて同じ価格スケールに乗る。
比較すべき軸は**価格 1 本だけ**で、時間足は比較の軸ではなく水準の出所にすぎない。

実測: 現在値のすぐ上に来る水準は `5m` → `1m` → `5m` → `1m` → `5m` → `15m` と**列をまたいで
交互に現れる**。行でも列でも一直線に読めず、**88 セルを総当たりで見比べるしかない**。
ラダーでは同じ問いが**現在値の隣接行**で決まる。

v0.2.0〜v0.3.0 で検討した「役割行 23 行 × 時間足 8 列」の表は、この理由により第 1 表としては採らない。
（役割の考え方はラダー各行のラベルとして生きる。詳細は §10。）

### 4.3 地平（horizon）— 「次のターゲット」は 1 つではない

「次のターゲット」＝ 現在値より上（下）で最も近い水準。これは**どの時間足の水準を数えるかで変わる**。

実測（1m 標本 390 本＝6.5 時間）:

| 含める水準 | 上 持続 | 上 距離 | 下 持続 | 下 距離 | 水準数 |
|---|---|---|---|---|---|
| すべて（1m 以上） | 1.5 分 | 10 点 | 1.5 分 | 10 点 | 88 |
| 5m 以上 | 2.1 分 | 16 点 | 2.0 分 | 17 点 | 78 |
| 15m 以上 | 3.7 分 | 54 点 | 3.9 分 | 39 点 | 68 |
| **1h 以上** | 8.3 分 | 127 点 | 6.6 分 | 166 点 | 58 |
| 4h 以上 | 16.2 分 | 140 点 | 10.2 分 | 176 点 | 46 |
| **1D 以上** | 77.8 分 | 342 点 | 21.6 分 | 209 点 | 34 |
| 1W 以上 | 389 分 | 1,834 点 | 29.9 分 | 245 点 | 18 |

距離・持続とも単調に増え、段が重ならない。**短期＝すべて / 中期＝1h 以上 / 長期＝1D 以上**の
3 段の直上・直下に「次」の印を付ける。

**持続は指名の安定性であって、当たるかどうかとは無関係である**（§9-1）。

### 4.4 束ねる案を保留にした記録

近接した水準を帯に束ねる案を検討したが採らない。測って分かったことだけ残す。

- 束ねても**「次のターゲット」の持続は伸びない**（帯幅 5 → 66 で 1.4 → 1.3 分と横ばい）。
  利点は行数が減ることだけだった。
- 「近ければ束ねる」と単純に連結すると**鎖状につながって 22 本・幅 252 点へ膨張**する。
  帯の**幅そのものに上限**を課さないと使えない。
- 帯は**現在値をまたぐ**（実測 1 件）。上下 2 分類で扱うと最も近い水準が表から消える。
  上 / 現在値を含む帯 / 下 の 3 区分が要る。
- 束ねない現行案では、この 2 つの問題はどちらも起きない。

### 4.5 指名が変わる原因（実測）

水準そのものはほとんど動かない（1m あたりの移動は中央 0.00 点。動くのは `1m` 水準だけで
中央 2.37 点）。一方、価格は 1 分で中央 12.9 点動く。

| 交代の原因 | 短期 | 中期 |
|---|---|---|
| 価格が前の目標を上抜けた | 46% | 40% |
| **前の目標は上に残ったまま、別の水準が割り込んだ** | **54%** | **60%** |

割り込む水準は短期で `1m`×64・`5m`×51 が大半。**短い足の水準が動いて目標を追い越している**。
これは価格の前進ではなく目標側の揺れであり、ISSUE-451（板注文）では発注管理の仕様に直結する。

## 5. 第 2 表（オシレータ水準到達表）の構造と、分位の価格投影

### 5.1 行と列

- **行** = 指標インスタンス（`ma_marod` / `btlm_trail_marod` / `profit_rsi` / `tickvol`）。
- **列** = 表示時間足 8 列。第 1 表と違い **MTF 共通列は無い**（現行設定に `timeframe` 明示の
  オシレータ instance が無いため）。
- **セル数** = 延べ 33（`ma_marod` のみ 1D に 2 本）。

### 5.2 セルの内容（v0.6.0 で段ラベルを廃止）

| 要素 | 内容 |
|---|---|
| **配色** | 連続量 `p ∈ [0, 1]`（§5.3）。**段の名前は表示しない**（依頼者裁定 2026-08-29） |
| 現在値 | その指標のその時間足での現在値（単位は指標ごと: % / 0–100 / tick 数） |
| 到達時刻 | 帯を出ているときのみ。定義 A（§6.2）を第 1 表と同一に適用 |

第 1 表と違い、現在値は指標ごと・時間足ごとに異なる。よって**現在値の独立行は流用できず**、
各セルが自分の現在値を持つ。色から絶対量は読めないため、**現在値の数字は必ず併記する**。

**水準が存在しないセルは隠さない。** 例: `1M` の `tickvol_gpd_hi` は観測 30 件
（`common.gpd.MIN_GPD_EVENTS`）未満で NaN になる。空欄にせず**水準なし**と明示する
（§7 の `cvfe` と同じ規約。無言の縮退を作らない）。

### 5.3 配色の基準 = 因果ローリング分位 `p`（v0.6.0 で確定）

段の名前（帯内 / 上帯超 / ext 超 …）は**廃止**した。セルは連続量 1 つで塗る。

```
窓  = values[max(0, t - window_n) : t]      ← 当該バー除外（common.marod_bands と同一規約）
p_t = 窓内で v_t 未満の割合                  ∈ [0, 1]

  0.0 ────────────────── 0.5 ────────────────── 1.0
  沈静                   中立                   過熱
```

既存の水準（`_q{pct}` / `_evq_*` / `_gpd_*`）は**この `p` のしきい値にすぎない**。よって `p` は
4 指標・8 時間足を通じて**同一の意味**を持つ唯一の量であり、新しい統計を作らない（単一ソース）。
これにより `tickvol` の段が他 3 種と非対称であること（下 1 段・上 4 段）も**表現の問題として消える**。

実測（2026-08-29）: `p` の 10 分割ヒストグラムは `1m`〜`1D` の全 4 指標で各ビン **8〜13%**、
`p = 0` / `p = 1` の張り付きは **2% 未満**。色域を偏りなく使い切る。

#### 5.3.1 帯の外側は GPD で解像する

`p` は上限 1.0 で頭打ちになる。実測で**正常帯を超えたバーの 3〜50% が `p = 1.0` に張り付き**、
「わずかに超えた」と「極端」が同じ色になる。**最も見たい所で色が止まる。**

```
帯内 : p = 経験順位（上記）                                    ∈ [0, q_high]
帯外 : p = q_high + (1 - q_high) * F_GPD(v - u ; xi, beta)      ∈ (q_high, 1]
```

`u` は正常帯上端（＝POT 閾値）。GPD は既存規約どおり**エピソード極値へ畳んだ超過分の
直近 `k_events` 件**へ当てはめる（`common.gpd` を無改変で使用）。

実測（2026-08-29・全 33 セル）:

| 指標 | 結果 |
|---|---|
| `p = 1.0` の張り付き | **3〜50% → 0.0%** |
| 目盛りの相異値 | 10〜144 → **157〜6,009** |
| 接合の跳び（`v = u` 直上） | **0.0000〜0.0031**（全幅の 0.31% 以下）＝連続 |
| 有限終端（`xi < 0`）の超過 | **0.0〜1.2%**＝無視できる |
| 単調性 | 構成上成立（`F_GPD` は超過分について単調増加） |

**有限終端（`xi < 0`）の終端以上は `p = 1.0` である**（分布関数の定義どおり。上表の
「有限終端の超過 0.0〜1.2%」が**そのまま `p = 1.0` に張り付く**）。`common.gpd.gpd_cdf` は
台の外を NaN で返す（数値計算上の表現であって分布の値ではない）ので、実装はここを
1.0 へ丸めてから接合式へ渡す。丸めないと**最も極端な観測だけ色が消える**——
表の 1 行目（張り付き 3〜50% → 0.0%）を達成しながら、最上位の 0.0〜1.2% だけが無色になる。

**参照実装との差分（明記する）**: `tools/measure/issue449/probe_tailscale.py:135-136` は
`gpd_cdf` の NaN を**素通し**する（同 `:131-134` で終端超過を件数として数え、統計からは
`np.isfinite` で外している）。参照実装は「終端超過が無視できる量か」を測るのが目的なので
クランプが要らない。表示側は 1 セルも無色にできないため実装側でクランプする。
**測る目的と塗る目的で扱いが分かれる箇所であり、参照実装からの逸脱ではない。**

**窓 `window_n` を伸ばして解像する案は採らない。** `levels.py` ③ の実測どおり水準は非定常
（履歴 4 分割の中央値が 3 倍動く）で、全履歴の当てはめは適合度検定で棄却される。

#### 5.3.2 GPD が当てはまらない 7 セルは、帯外を単一色にする

#### 5.5.2 前進評価の形（実測 2026-08-29・`probe_inverse.py`）

各指標の core を**無改変で前進評価**し、現在バーの終値 `C` に対する指標値 `v(C)` を測った。
逆関数の数式は書いていない（参照実装があるものを推測で実装しない）。

**`v(C)` は区分メビウス `(aC + b) / (C + d)` である。**

| 指標 | 区分数 | 3 点当てはめの残差（最大） | 単調性 |
|---|---|---|---|
| `ma_marod` | 3 | 6.0e-14 | 増加 |
| `btlm_trail_marod` | 3 | 6.0e-14 | 増加 |
| `profit_rsi` | 6 | 3.9e-12 | 増加 |

区分の境目は**適用価格 hlc3 の折れ**（走行 H / L。`C` が高値を越えれば高値も動く）。
`profit_rsi` はさらに**上下分岐**（`x_t` が `x_{t-1}` を跨ぐ点）が加わる。

ここから 2 つが確定する。

- **逆写像は近似ではなく閉形式で厳密**である: `C = (b − v·d) / (v − a)`。
  反復探索・ニュートン法・二分法はいずれも要らない。
- **全区分で単調増加**である。よって価格の交差による到達判定が指標値の交差と**同値**になり、
  §6.1 の判定規約をそのまま適用できる。**判定を二重に持たない。**

#### 5.5.3 構造（指標側が実装するのは境目だけ）

```
BreakpointSource（指標ごと）      : breakpoints() -> [価格]        ← これ 1 メソッドのみ
PriceValueMap（指標を知らない）   : fit(forward, breakpoints)      ← 区分ごとに 3 点で係数を決める
                                   value_at(price) / price_at(value)
```

- `forward(C) -> value` は**既存の増分器をそのまま呼ぶ**。指標の core は 1 行も変えない。
- **逆関数の数式を指標ごとに手書きしない**。逆写像はメビウス当てはめ 1 か所が所有する
  （同じ計算の第 2 定義を作らない・§8「単一ソース」）。

#### 5.5.4 費用（実測 2026-08-29・`probe_heatmap.py`）

`v(C)` がメビウスなので、**係数を決めた後の価格評価は前進評価を一切呼ばない**。

```
係数決定             : instance あたり 区分数 × 3 回（marod 9 回 / RSI 18 回）
ラダー 82 行の評価   : 発行 0 回       （参照実装を直接呼ぶなら 2,050 回）
閉形式と直接呼び出しの最大差 : 1.1e-08
```

係数は**現在の価格 `C` に依存しない**（前バーの状態と走行 H / L だけで決まる）。よって
再計算の契機は**バー確定と走行極値の更新のときだけ**であり、ティックごとではない（§7）。

#### 5.5.5 塗る単位 = 地平 3 分割（2026-08-29 承認・v0.6.1 で `p` へ統一）

## 6. 到達判定と到達時刻の導出（両表に共通）

### 6.1 判定（交差）

水準はバーごとに動くため、固定値との比較では判定できない。バー系列 `t` に対し

```
reached_t := (value_t >= level_t)      # 上側水準は方向を反転
                                       # value = 第1表なら価格・第2表なら指標値（§2 観測値）
```

現在の到達状態は最新点の `reached` である。

### 6.2 到達時刻（定義 A）

現在の到達状態が始まった時刻 = **`reached` が現在と同値である連続区間の始端の時刻**。

```
first_t := min{ s | reached_s = reached_now  かつ  ∀u∈[s, now] : reached_u = reached_now }
```

観測値が水準を離れて戻ると、戻った時点が新しい `first_t` になる。

### 6.3 クライアント側で積み上げてはならない（根本要件）

到達時刻をフロントで観測しながら積み上げると、**シートを開いた時刻に依存**し、開き直すたびに値が変わる。
これは表示の欠陥であり、選択肢ではない。到達時刻は必ず**水準系列と観測値系列の履歴の突合**から導出する。
履歴は既存 `full_compute`（`adapter/compute/latest_dispatch.py:27-31`）が返す全件系列で足りる。
新規の統計・新規の保存領域は不要。

## 7. 更新経路（2 段）

| 段 | 契機 | 経路 | 内容 |
|---|---|---|---|
| 1 | バー確定 | `/compute`（全件系列） | 水準系列と観測値系列を突合し、全セルの水準値と到達時刻を再導出する |
| 2 | ティック | `/live_ticks` の tails | 観測値を更新し、到達状態（第 1 表は行の価格降順の並びも）を更新する |

**2 段は素材の側でも構造になっている（v0.6.4・ISSUE-457）。** 段の区別を「何を再計算するか」の
文章に留めると、実装は毎要求すべてを作り直す（実際にそうなっていた。§9-4）。素材を次のとおり
分けることで、段の区別を機械が守る形にした。

| 素材 | 不変な範囲 | 誰が持つか | いつ作り直すか |
|---|---|---|---|
| 確定足ぶんの full 系列 | その時間足の周期（epoch）の中 | プロセス寿命のストア（キー = `(datasetRef, 時間足)`・版 = `period_start_unix`） | その時間足の周期が進んだとき **だけ**（＝段 1） |
| 形成中足の 1 点 | 不変でない（ティックごとに動く） | 誰も持たない（毎要求作る） | 毎要求（＝段 2。増分ディスパッチ 1 点ぶん） |
| 足の DataFrame（現在値・走行 H / L） | 不変でない | 誰も持たない（毎要求読む） | 毎要求（実測 1〜6 ms/足） |

**鮮度は共有と引き換えにしない。** 現在値・走行 H / L は毎要求読み直した素材から取り、系列の
末尾点は毎要求作り直す。したがって共有によって古くなる値は 1 つも無い（応答は是正前と完全一致
することを実測で確認した）。ある時間足の周期が進んでも、作り直すのはその時間足の素材だけである。

**版は「どの周期か」だけでは足りない。** 周期が進まないまま確定素材が入れ替わる経路が実在する
（ロールアップの再生成・読み取り時の外れ値補正の変更・供給の遡り訂正）。周期だけを版にすると
その差し替えを 1 周期ぶん（`1M` なら 1 か月）見落とすため、版は窓の署名
（周期の始端・本数・窓の先頭時刻・窓の末尾の終値）で持つ。§5.3.1 の GPD 当てはめキャッシュが
「本数だけを署名にしてはならない」としているのと同じ理由である。**速いことより古い素材を
配らないことが優先する。**

**末尾 1 点を出せない系列がある。** 増分器の宣言は系列ごとであり、宣言の無い系列は確定足で
終わる（＝チャートでティックごとに動く線と動かない線の区別に一致する）。実測 2026-08-30 の
該当は `profit_rsi` の帯外 4 系列（`rsi_evq_ext_hi` / `rsi_evq_ext_lo` / `rsi_gpd_hi` /
`rsi_gpd_lo`）だけであり、**第 1 表の水準にも第 2 表のセルにも使われていない**。粒度の差が
シートの読む系列に及んだときは縮退として出す（instance 単位の縮退一覧では系列ごとの差を
表せないため、そのときは表し方から設計し直す）。

段 2 の対象は足内更新を宣言済みの指標に限る。`cvfe` は増分器が無いため段 1 のみで更新される
（`adapter/compute/live_tick_tails.py` が `None` を返し、ティック更新から明示的に落ちる）。
これを隠さず、`cvfe` 行には更新粒度がバー確定であることを表示する。

第 2 表の 4 種はすべて増分器を宣言済みで、段 2 で更新される（更新粒度の差は生じない）。

**§5.5 の価格投影（背景色）の更新契機は 3 段目ではない。** メビウス係数は現在の価格に依存せず、
前バーの状態と走行 H / L だけで決まる（§5.5.4）。したがって:

| 契機 | 係数の再当てはめ | 背景色の再計算 |
|---|---|---|
| バー確定 | **要**（instance あたり 区分数 × 3 回の前進評価） | 要 |
| 走行 H / L が更新された | **要**（同上） | 要 |
| 上記以外のティック | **不要（0 回）** | 要（閉形式のみ。前進評価は発行しない） |
| ラダーの行が増減した | **不要（0 回）** | 要（閉形式のみ） |

**計算量テスト（CLAUDE.md 絶対命令 §4.1・実装時に必ず添える）**: 本シートは既存系列を読むだけであり、
新規の計算を発行してはならない。よって Test Spy で「シートが発行した compute 呼び出し数 −
既にチャートが発行している呼び出し数 = 0」を表明する。加えて**行数・列数を増やしても発行が増えない**
ことを 2 点以上（例: 11 行 / 23 行）で固定する。回数そのものは期待値に焼き込まない。

**§5.5 の価格投影に固有の計算量テスト**: `forward` を Test Spy で数え、次を表明する。
回数そのもの（9 や 18）は**期待値に焼き込まない**。固定するのは無駄の不在である。

- **無駄の不在**: 発行した前進評価 − 係数決定に使った前進評価 = **0**。
- **オーダーの表明（行数）**: ラダー行数 82 → 164 で発行回数が**変わらない**（2 点固定）。
- **オーダーの表明（水準数）**: 1 instance の水準 6 本 → 12 本で発行回数が**変わらない**。
- **オーダーの表明（ティック）**: バーが確定せず走行 H / L も更新されないティックでの発行が **0**。

「行として足す案」（§10）はこの 4 つを 1 つも満たせない（行数・水準数の両方に比例するため）。

**§5.3 の連続配色に固有の計算量テスト**: `p` は既存系列（値・帯・イベント分位）から導く量であり、
**新規の compute を発行してはならない**。回数そのものは期待値に焼き込まない。

- **無駄の不在**: 連続配色が発行した compute 呼び出し − 既にチャートが発行している呼び出し = **0**。
- **GPD の再当てはめはイベント確定のときだけ**。エピソードが閉じないバーでの当てはめ回数が **0**
  であること（`p` を求めるたびに当てはめ直さない）。
- **オーダーの表明**: 表示するセル数を 33 → 66 にしても、当てはめ回数が**変わらない**こと。
- **§5.3.3 の経過割合別分布**: 保持する分布の本数が**ティック数に比例しない**こと
  （1 バー内で何ティック来ても、更新は経過割合の刻みごとに 1 回）。

**素材の共有に固有の計算量テスト（v0.6.4・ISSUE-457）**: 段の区別は**要求をまたいで**しか
観測できない。1 要求の中だけを見る検査は、毎要求作り直す欠陥を 1 件も落とさない（実際に
落とさなかった）。よって次の 3 つを固定する。回数そのもの（40 や 81）は焼き込まない。

- **無駄の不在**: epoch が 1 つも進まないまま同じ要求を繰り返しても、確定素材の発行の
  **追加が 0**。繰り返し数を変えた 2 点（5 / 20）で固定する。
- **発行の局所性**: ある時間足の周期だけが進んだとき、作り直すのはその時間足の素材だけで
  あり、他の時間足の追加発行は **0**。進めた回数を変えた 2 点（1 / 3）で固定する。
- **鮮度**: 形成中足が動いただけのときは追加発行 **0** のまま、足の末尾と系列の末尾点が
  **新しい値になる**。共有と引き換えに値を古くしていないことを、共有と同じ検査で押さえる。

結線（Composition Root がストアを 1 つ持ち、要求ごとの口へ渡す）は**実 HTTP で固定する**。
受け口をいくら正しくしても、ストアを渡し忘れれば無言で毎要求作り直しに戻り、単体検査では
落ちない（ISSUE-291 と同型）。

### 7.1 本書と実装の差異を赤で落とす（契約テスト・v0.6.2 で追加）

計算量テスト（上記）が防ぐのは「**無駄な計算**」であって、「**本書と実装の食い違い**」ではない。
これは別の欠陥であり、**別の検査が要る**。

#### なぜ必要か（本書で 2 件・監査で 142 件、いずれも全緑）

| 実例 | 本書の記述 | 実装 | 検出 |
|---|---|---|---|
| ISSUE-454 | 「`tickvol` は下側の段は持たない」（v0.5.1 §5.3） | `tickvol_q10` を出力している | **人手**（実値を測って発覚） |

**本書を検査するテストが 1 本も存在しない**ことが原因である。

#### 何を固定するか

本書が実装について述べる**列挙可能な事実**だけを対象にする。文章の言い換えは対象にしない。

| 対象 | 本書の出典 | 実装側の真 |
|---|---|---|
| 各指標が出す**系列名の集合** | §3.1 / §3.2 | `/compute` の実応答（`series[].name`） |
| **足内更新の可否** | §3.1「足内更新」列・§7 | 増分器 factory への登録有無 |
| `MIN_GPD_EVENTS` の値 | §5.3.2 | `common.gpd.MIN_GPD_EVENTS` |
| **価格へ逆算できる指標**の集合 | §5.5.1 | `breakpoints()` を提供する実装の集合 |
| `v(C)` の**単調性** | §5.5.2 | 参照実装の前進評価（性質テスト） |

#### どう書くか（監査が挙げた 3 つの失敗形を踏まない）

監査が挙げた「赤くならないテスト」の形は 3 つある。本節の検査はいずれも踏まない。

| 失敗形 | 本節での回避 |
|---|---|
| 実装のソース文字列を grep して「実装がある」と主張する | grep しない。**実 `/compute` の応答**と突き合わせる |
| 期待値を被検査コードの式から生成する（トートロジー） | 期待値は**本書から読む**。実装からは 1 つも作らない |
| 本番が通らない経路だけを fake で叩く | 本番と同じ `/compute` を通す。fake を挟まない |

**期待値の出所が本書であることが本検査の核心である。** 実装から期待値を作ると、食い違いは
定義上起きなくなり、検査は何も守らない。

そのために、本書の列挙を**機械可読ブロック**（下記 §7.1.1）として置く。検査はこれを読み、
実応答と集合比較する。§3.1 / §3.2 の表は人間向けの写しであり、**両者が一致することも
同じ検査で固定する**（複製を禁止するのではなく、複製を機械的に縛る）。

- ブロックが実装より**多い**（本書にあるが出力されない）→ 赤。
- ブロックが実装より**少ない**（出力されるが本書に無い）→ 赤。
  ISSUE-454 の `tickvol_q10` はこちらで落ちる。

## 8. 設計方針（SOLID 写像）

- **OCP**: 既存の compute・指標定義・チャート UI を改変しない。シートは既存の計算結果を読む追加の購読者。
  §5.5 の価格投影も同じで、各指標の core・第 1 表の行構造・第 2 表はいずれも**無改変**。
  追加は「価格 → 段」を返す問い合わせ口 1 つだけである。
- **単一ソース**: セルの計算式を写さない。水準＝既存系列、到達＝既存系列同士の比較。計算の第 2 定義を作らない。
  §5.5 では**逆関数の数式を指標ごとに手書きしない**。逆写像は `PriceValueMap` 1 か所が所有する。
- **DIP**: 交差判定・到達時刻導出・行の並び替えは純関数（DOM・HTTP・localStorage 非依存）。
  §5.5 の当てはめは既存の増分器を `forward(C) -> value` として抽象越しに呼び、具象指標へ依存しない。
- **ISP**: 既存の TailSpec 契約（`instanceId` / `indicatorId` / `variant` / `params`）をそのまま使い、広げない。
  §5.5 で指標側が実装するのは `breakpoints()` **1 メソッドのみ**（逆関数の数式は要求しない）。
- **SRP**: `PriceValueMap`（当てはめと逆写像）と `BreakpointSource`（区分の境目）を分ける。
  前者は指標を知らず、後者は数式を知らない。
- **LSP**: §5.5 の 3 指標は同一契約を満たす。`tickvol` は `breakpoints()` を提供できず、
  **対象外が構造で表れる**（列挙による除外を書かない）。
- **§5.3 の連続配色**: 配色は `p` 1 つに依存し、指標を知らない（**SRP**）。`p` の求め方は
  「帯内＝経験順位／帯外＝GPD」の 1 定義だけで、指標ごとに書き分けない（**単一ソース**）。
  §5.3.3 の「同じ経過割合の分布へ当てる」は**積み上がる量かどうか**という 1 つの性質で
  切り替わる。`tickvol` を名指しで分岐しない（**OCP**。将来 tick 数以外の計数量が増えても
  同じ性質の宣言だけで載る）。

## 13. 到達率・到達までの時間・反応の実測（2026-08-29）

### 13.1 定義（本測定で固定する）

| 語 | 定義 |
|---|---|
| 標本 | **60 分ごと**の 1m 足（834 点）。価格は 1m close |
| 指名 | その地平で、価格より上（下）にある最も近い水準の値 `v` |
| 到達 | `v` を**固定した目標**として、以後 K 分以内に 1m high ≥ `v`（上）/ low ≤ `v`（下）。固定するのは指値を発注時の価格に置くのと対応させるため |
| 反応 | 到達後、`v` から X 点**戻る**のと X 点**進む**のどちらが先か。戻るが先＝反転 |
| 対照 | **別の時刻・同じ距離**で、どの水準からも 15 点以上離れた価格。距離を厳密に揃え、水準性だけを外す |

### 13.2 到達率・到達までの時間

| 地平 | 向き | 件数 | 距離（中央） | 到達率 | 到達まで（中央） | 観測窓 |
|---|---|---|---|---|---|---|
| 短期（全部） | 上 / 下 | 834 / 834 | 11 点 / 11 点 | 95% / 95% | 1 分 / 1 分 | 120 分 |
| 中期（1h 以上） | 上 / 下 | 834 / 834 | 95 点 / 87 点 | 86% / 86% | 16 分 / 16 分 | 480 分 |
| 長期（1D 以上） | 上 / 下 | 834 / 834 | 304 点 / 277 点 | 78% / 84% | 119 分 / 122 分 | 2880 分 |

**これは使える**。「その価格までどれくらいか」の見積もりになる。ただし**距離で決まる量**であり、
水準であることの効果ではない（同じ距離の任意の価格でも同じになる）。

### 13.3 反応 — 水準に情報は無かった

| 地平 | 向き | 水準 反転率 | 対照 反転率 | 差 | z |
|---|---|---|---|---|---|
| 短期 | 上 / 下 | 77% / 79% | 81% / 83% | −3.5 / −5.0pt | −1.7 / −2.5 |
| 中期 | 上 / 下 | 87% / 90% | 89% / 90% | −1.8 / +0.3pt | −1.0 / +0.2 |
| 長期 | 上 / 下 | 89% / 92% | 91% / 95% | −2.4 / −2.6pt | −1.5 / −1.9 |

反応幅を 30 点にしても差は −5.4 〜 +2.8pt（|z| ≤ 2.3）で符号が一定しない。
**12 比較で |z| ≤ 2.5 は多重性を考えれば有意でない**（Bonferroni の閾値は約 2.9）。

> **結論: 水準に到達しても、同じ距離の「水準でない価格」に到達した場合と反応は変わらない。**
> 「水準に到達したら反発する」という前提は、この測定では支持されない。差があるとすれば
> むしろ**水準のほうがわずかに反転しにくい**方向だが、これも有意でない。

### 13.4 この結論が効く範囲

- **本シート（表示）には影響しない。** ラダーは「価格がいまどこにあるか」を示すものであり、
  反発を予言していない。到達率・到達時間（§13.2）は表示に添える情報として使える。
- **ISSUE-451（板注文）には決定的**。「水準に指値を置けば有利」を前提にできない。
  発注の根拠は別に要る。

### 13.5 第 1 版の欠陥（記録）

最初の測定は到達率 88〜96% を出したが、**エピソード始端だけを標本にした偏り**だった。
新しい目標は「価格が直前の目標を通過した直後」に現れるため、始端は価格のすぐ近くに偏る
（中期の距離が、全標本 127 点に対し始端 35 点）。周期標本へ変えて是正した。
対照も当初は `v ± (20〜60)` 点にずらしており距離が揃っていなかったため、
**別の時刻・同じ距離**へ変更した。

### 13.6 限界（この結論を超えて一般化しない）

- 1 銘柄（JP225）・52 日・現行テンプレート 1 設定のみ。
- 反応の定義は「先に X 点戻るか進むか」（X = 15 / 30）。他の定義（滞留時間・出来高反応）は未測定。
- 到達率は観測窓 K に依存する。K は地平の持続に合わせて選んだ（120 / 480 / 2880 分）。

## 14. 各時間足チャート一覧（ISSUE-452 内容 2・v0.7.0）

依頼者指示（2026-08-30）「『ダッシュボード』項目に各時間足の水準が確認できるチャートの一覧を
表示しろ」「価格ラダーは左側、チャートは右側に表示しろ」で、ISSUE-460 まで**案・未確定**だった
本項目を実装として確定した。

### 14.0 目的（依頼者言明 2026-08-30・チャート一覧の存在理由）

チャートを表示する理由は次の 2 つ**だけ**である。機能追加の判断はこの目的に照らして行う
（目的に寄与しない飾りは足さない——認知負荷の最小化）。

1. **価格ラダーを視覚的に確認する** — ラダーの行（数値の羅列）が実際の値動きのどこに
   在るかを、同じ応答の水準線として目で確かめる。
2. **水準を確認する** — 各時間足の水準そのもの（位置・現在値との位置関係・支持/抵抗の別）を
   チャート上で読む。

この目的から導かれる既定: 水準線の源は第 1 表と**同一応答**（照合対象がずれたら目的 1 が
壊れる・§14.2）。目盛りはローソクの値幅に従う（目的はあくまで値動きの文脈で読むことであり、
遠い水準まで 1 枚へ押し込んで足を潰さない。表示域の外の水準はラダー側が担う）。

### 14.1 形

- **1 時間足 = 1 タイル**（§3.4 の 8 本・表示順は `timeframes.js` の唯一源）。タイルは
  **4 列 × 2 段の固定グリッド**（依頼者指示 2026-08-30・v0.7.8。各タイル幅は列の 1/4 均等割り。
  幅で列数が揺れる auto-fill は廃止＝8 時間足が常に同じ位置）。チャート節は自分の grid 領域の
  **100%** を使う（中央寄せ上限から除外・外周余白なし。v0.7.3）。
- 各タイル = 当該時間足のローソク（確定足・末尾 180 本）＋**当該時間足の水準の価格ラベル**。
  水準は**価格スケール上のラベルだけ**で示し（ラダーの価格の値・支持/抵抗の色）、チャートを
  横断する線は引かない（過去まで伸びる線は判断を迷わせる・依頼者指示 2026-08-30・v0.8.0）。
  現在値の独自の線・ラベルも置かない（ローソク系列の最終値表示とラダーの現在値行が担う・
  v0.7.9→v0.8.0）。チャートの縦幅は
  clamp(360px, 45vh, 640px)——**水準の確認には縦幅（価格方向の分解能）が要る**
  （依頼者指示 2026-08-30・§14.0 目的 2 の要件）。
- 水準ラベルの色の意味はラダーの凡例と同一（現在値より下＝到達済み＝支持側／上＝抵抗側）。
- 版面: **左列＝価格ラダー＋オシレーターラダー（縦積み）・右列＝チャート一覧**。左列の幅は
  **価格ラダーの全列が横スクロールなしで収まる内容幅**（依頼者指示 2026-08-30・v0.7.4。
  同日の 70% 固定裁定を上書き）で、チャートは残り幅を全て使う。置き場所の唯一源は
  dashboard.css の `grid-template-areas`（1100px 以下は左列の読み順で縦積み）。
  View は並び順を知らない。

### 14.2 データ経路（二重発行の禁止・ISSUE-452 の不変条件）

- **水準・現在値**: `/reach_sheet` の**同じ応答**を第 1 表と共有する（チャートのための計算・
  取得を 1 本も増やさない）。描画は価格線の**差分適用**（同一応答の再描画で発行 0・
  価格移動は applyOptions・消えた線だけ remove）。
- **ローソク**: live core の `GET /candles` から**借りる**（period_presets と同じ規約。
  dashboard core に配信面を複製しない）。再取得は**その時間足のバー枠が進んだときだけ**
  （枠内の取り直しは応答が同じ＝丸ごと浪費）。lwc（lightweight-charts）を使えない環境では
  理由を文字で掲示し、**取得自体を行わない**。
- 上記はすべて計算量テストで機械的に固定（charts_paint_complexity / candle_poller /
  composition_root_front の各検定。回数は焼き込まず、期待値は入力から導出）。

### 14.3 縮退の掲示（無言禁止・§5.2 と同じ規約）

- lwc 不在: 「チャート描画ライブラリが読み込まれていない」を版面へ掲示。
- ローソク取得失敗: 当該タイルの見出しへ理由を掲示（空チャートと区別できる形）。
- 応答失敗: 理由を掲示し、線とローソクは前回の正常応答のまま（失敗のたびの明滅を作らない）。
