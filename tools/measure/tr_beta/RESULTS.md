# 真の値幅の β で、この先の値幅の増減を当てられるか（2026-10-31）

依頼（2026-10-31）: 「真の値幅の β の検定に着手しろ」。
前段の提案: 真の値幅の β の符号で、次の 20 本の平均が今より大きくなるかを当てられるか、円環ずらし帰無で検定する。

## 1. 事前登録（実行前に記録・結果を見てから変えない）

### 1.1 データ（`.doc/VALIDATION_PROTOCOL.md` §2）
| 用途 | 系列 | 期間 |
|---|---|---|
| 選ぶ期間（IS） | `rollups/jp225_tick_bid/`（Dukascopy） | 2014-01-01 〜 2020-04-30 |
| 確かめる期間（OOS） | `rollups/jp225_mt5/`（MT5） | 2020-05-01 〜 最後の確定足 |

時間足は 1h・1D。2 系列は連結しない。β はこれらの期間で一度も調整していない。
水準の見積もりにワイルダーの平滑 14 を選んだ前回の比較は同じ期間を見ているので、水準の見積もりの良さの証拠ではない。

### 1.2 系列
- x = 真の値幅 ÷ 前の足の終値 × 100（%）。価格帯による単位の偏りを除く。
- 1h のみ、x を時間帯の中央値で割る（期間ごとに 24 個の係数）。時間帯の周期を残すと、円環ずらしで周期が壊れ、見かけの有意が出るため。
- 計算は期間の終わりまでの足だけで行う。IS は先頭に 2014-01 より前の足を助走に使う。

### 1.3 測る量（足 t ごと）
- β: x の直近 n 本の OLS の傾き（btlm_trail の `rolling_ols_window_end` をそのまま使う）。n = 20・50・100。符号だけを使う（0 は除く）。
- A: 直近 20 本の x の平均。Y: 次の 20 本（t+1〜t+20）の x の平均。W: x のワイルダーの平滑 14。

### 1.4 検定（時間足 2 × n 3 = 6 組）
- 検定 1（依頼どおり）: β > 0 と Y > A の一致率 H。
- 検定 2（水準を除いても残るか）: e = log Y −（a + b log W）。D = β > 0 の e の平均 − β < 0 の e の平均。a・b は IS で時間足ごとに最小二乗で決め、OOS でも同じ値を使う。

検定 1 だけでは足りない理由: β > 0 の足は A が高いことが多く、値幅の平均回帰だけで Y < A に偏る。この偏りは円環ずらしで壊れるので、検定 1 の有意は「水準」の情報でも出る。
そのため「β ならではの情報があるか」は検定 2 で判定する。

### 1.5 帰無と p
- 目的の系列（Y > A、または e）を β に対して円環状にずらす。ずらし幅は [250, N − 250] の一様乱数・1,999 個・seed 20261031。
- 両側 p =（1 + |帰無 − 帰無の平均| ≥ |実測 − 帰無の平均| の回数）÷ 2000。
- IS: 検定ごとに 6 組で Holm 法。0.05 未満を通過。
- OOS: IS を通過した組だけで Holm 法。0.05 未満かつ IS と同じ向きで通過。

### 1.6 判定
- 検定 1 が通過: 値幅の増減の向きと関係がある。H が帰無より低ければ「β と逆に動く」と書く。
- 検定 2 が通過: 水準を除いても β に情報がある。
- 実用: 検定 2 を通過した組について、見積もり ŷ = exp(a + b log W + c·sign β)（c は IS の最小二乗）の外れ（外れの平均 ÷ Y の平均）が、c なしより OOS で 0.5 ポイント以上小さいこと。
- どれも通らなければ「β で当てられるとは言えない」と結論する。閾値はこの後で変えない。

### 1.7 計算量の検定
`beta.py` は平均・β・帰無の計算を注入点で受け、発行回数 − 使った回数 = 0 と、入力を増やしても発行が増えないことを `test_beta.py` で固定する。

## 2. 結果（`tools.measure.tr_beta.run`・出力 `results/tests.csv`）

MT5 の最後の確定足は 2026-10-15 16:00 の 1h 足。p の下限は 0.0005。帰無の一致率はどの組も約 0.50（0.498〜0.505）。

### 2.3 判定（§1.6 の基準のまま）
- 検定 1: 5 組が通過。n = 20 は β と同じ向き、n = 50・100 は β と逆に動く。β の向きと値幅の増減の関係は、n によって符号が変わる。
- 検定 2: 1h の n = 50・100 が通過。向きは負で、β > 0 のほうが水準から見た次の 20 本の値幅が小さい（OOS で約 4〜6%）。
- 実用: 通過した 2 組の外れの改善は 0.04・0.10 ポイントで、基準の 0.5 ポイントに届かない。**不合格**。
- 結論: **β に統計的な情報はあるが、次の 20 本の値幅の見積もりを実用的に良くする大きさではない。**「β が正なら値幅はこの先も増える」という読み方は、検定 1 を通過した 1h の n = 50・100 と 1D の n = 50 では実測と逆である。

### 2.4 未検証・限界
- 時間帯の係数は期間全体の中央値で決めている（期間内の先読み）。検定の目的は周期を除くことで、売買の再現ではない。
- n = 20 の検定 1 の同じ向きが、窓の作り（β > 0 なら A の中で古い足が低い）だけで説明できるかは測っていない。
- 検定 2 の負の向きの理由は §1 では測っていない。§4 の事後の確認を参照。
- 時間帯の補正は曜日の周期を消さない。独立レビューが登録外の確認として 1h の D を整数週ずらしで再検定し、n = 50・100 の判定は変わらなかった。整数日ずらしでは IS の n = 50 が Holm 後 0.062 になり、曜日の位相の混合で帰無の幅が広がる。

## 3. 独立レビューと実行後の修正（2026-10-31）

code-review-executor の独立レビューの結果、数値・判定を変える欠陥は 0 件。別の seed 20 個でも通過する組は同じだった（レビューの実測）。検査の不足を次のとおり直した。§1 の基準と §2 の数値は変えていない。

- β の計算を、§1.3 の `rolling_ols_window_end` から同じ窓の計算の公開入口 `window_end_scalar` に変えた。評価しない助走の窓（IS で 13〜19%）を発行しないため。同じ値になることを `test_beta_sign_equals_the_rolling_calculation_of_btlm_trail` で固定した。窓の中で β 以外の量も計算される点は、btlm_trail を改変しないので残る。
- OOS の Holm・向き・実用の判定を `run.py`（`beta.judge`）に入れ、`results/tests.csv` の列（`*_holm`・`*_pass`・`err_gain`・`usable`）で再現できるようにした。§2 の手計算と一致した。
- 計算量検定を、発行と p の計算に届いた本数の差、発行した窓と出力の差、助走の長さを変えた 2 点の比較に直した。
- 修正前後の `tests.csv` の数値の差は最大 3e-20（§2 の表の値は同じ）。
- テストの有効性: `beta.py` の変異 16 種をメモリ上で適用し、すべて検出した（手順: 1 か所を置換したモジュールで `test_beta.py` の全関数を実行し、1 件以上失敗するか数えた）。

## 4. 事後の確認: 改善は btlm_trail の β ならではのものか（事前登録の外・`run_attrib.py`・`results/attrib.csv`）

依頼者の指摘（2026-10-31）: 「この改善はbtlm_trailの改善とは説明できない。」

確かめたこと: 1h の n = 50・100 で、W に足すものを β の符号と n 本の単純平均 L で比べる。係数は IS で決め直し、外れは OOS。
§1.6 の外れの改善は a・b を固定して c だけを足した値なので、ここの値とは一致しない（差は主に a・b の決め直しで生じる）。
単位の「ポイント」は外れの率の差（%ポイント）で、価格のポイントではない。

時間帯の補正を 2 通りで測った。「OOS の係数」は §1.2 のとおり OOS 全期間の中央値（先のデータを含む）。「IS の係数」は IS の中央値（先のデータを含まないが、データの業者が違う）。

| 時間帯の補正 | n | β を足す（95% の幅） | L を足す（95% の幅） | L にさらに β を足す（95% の幅） | L − β の 95% の幅 |
|---|---|---|---|---|---|
| OOS の係数 | 50 | 0.022（−0.04〜+0.08） | 0.015（−0.06〜+0.08） | +0.008（−0.01〜+0.03） | −0.05〜+0.03 |
| OOS の係数 | 100 | 0.073（−0.02〜+0.18） | 0.100（−0.05〜+0.24） | +0.013（−0.02〜+0.04） | −0.08〜+0.13 |
| IS の係数 | 50 | 0.054（−0.01〜+0.11） | 0.095（+0.01〜+0.17） | −0.005（−0.02〜+0.01） | −0.00〜+0.09 |
| IS の係数 | 100 | 0.077（−0.01〜+0.18） | 0.203（+0.05〜+0.34） | −0.010（−0.04〜+0.02） | +0.01〜+0.23 |

95% の幅は週を単位にした再標本（1,999 回）。偏回帰の傾きの p は全ずらし（N − 2 × 250 + 1 通り）の数え上げ。

| 時間帯の補正 | n | β の p（OOS） | L の p（OOS） | β の係数（OOS・単独 → L あり） |
|---|---|---|---|---|
| OOS の係数 | 50 | 0.014 | 0.306 | −0.015 → −0.012 |
| OOS の係数 | 100 | 0.008 | 0.001 未満 | −0.029 → −0.016 |
| IS の係数 | 50 | 0.981 | 0.001 未満 | −0.018 → +0.001 |
| IS の係数 | 100 | 0.187 | 0.001 未満 | −0.031 → −0.008 |

IS での β の p は 0.041・0.057、β の係数（単独 → L あり）は −0.021 → −0.011、−0.031 → −0.013。β の符号と log(W ÷ L) の相関は OOS で 0.73・0.66。

- L にさらに β を足した改善の 95% の幅は、4 条件すべてで 0 を含む。IS の係数では改善の値そのものが負。
- β だけを足した改善の幅も、4 条件すべてで 0 を含む。L の改善の幅は IS の係数で 0 を含まない。
- 結論: **この改善を btlm_trail の改善とは説明できない。** L を入れたあとに β を足しても改善が増えるとは言えない。
- β に小さな情報が残るかは時間帯の補正で変わる（p 0.014・0.008 と 0.981・0.187）。どちらの補正が正しいかは決めていない。レビューの対照（OOS の最初の 2 年の係数と OOS 全体の係数がほぼ同じ結果）から、差の原因は先読みより業者の違いと見ている（推論・未検証）。
- §1.6 の式（a・b 固定）の改善の幅はレビューの実測で、IS の係数なら 0 を含まない（+0.020〜+0.134、+0.024〜+0.219）。「β を足す」が単独で 0 と区別できないのは、係数を決め直したこの節の式の話である。
- 登録外で多重比較の補正はしていない。

### 4.1 この節の訂正の経緯
- 初版は「W と L を除くと β の差は有意でない」「β は重なる情報を持つだけ」と書いた。2 回目の独立レビューで誤りと分かった。初版の統計量は β の符号から W・L を除いておらず、実測値が半分前後に縮んでいた。
- 第 2 版は「改善そのものが 0 と区別できない」「OOS で p が 0.01 未満」「β の係数は半分前後に縮む」「平均を足しても同じ程度」と書いた。3 回目の独立レビューで、順に、OOS の係数の条件でしか成り立たない、1,999 回の抽出のばらつきで実は 0.014、IS だけの話、幅が 0 を含むことは同等の証明でない、と分かった。この版で直した。
