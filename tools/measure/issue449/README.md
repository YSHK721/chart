# ISSUE-449 実測スクリプト（水準ラダーの設計根拠）

`.doc/PRICE_LEVEL_REACH_SHEET_BASIC_DESIGN.md` の **§4.3（地平）** と **§13（到達率・反応）**
の数値を出したスクリプト。設計書は実測値を根拠に書かれており、**その実測を再現できる状態を
保つため**に置く（数値だけ残して手順を失うと、後から検証も更新もできない）。

## 前提

1. **ライブ計算サーバが動いていること。**
   `./unified_ui/serve.sh`（公開 8000・ライブ core は内部 8001）。
   別ポートなら `ISSUE449_API` で指定する。
2. **チャートテンプレートの export（`export.json`）を作業ディレクトリへ置くこと。**
   ブラウザの localStorage から `indicatorUi.templates.v1` と
   `indicatorUi.templateBindings.v1` を取り出し、次の形で保存する:

   ```json
   {"templates": "<templates.v1 の生文字列>", "bindings": "<templateBindings.v1 の生文字列>"}
   ```

   これは利用者の設定そのもの（どの時間足にどの指標を置いているか）なのでリポジトリには含めない。
   **測定結果は設定に依存する**——設定が変われば水準の本数も距離も変わる。

## 使い方

```bash
export ISSUE449_DIR=/path/to/work      # export.json を置いた場所。生成物もここへ出る
export ISSUE449_API=http://127.0.0.1:8001

python3 probe_levels.py                # 素材の取得（52 日ぶん・実測 14 秒）→ long.json
python3 analyze_reach.py               # §13: 到達率・到達までの時間・反応
N=390 ISSUE449_SRC=long.json \
  python3 analyze_horizon.py           # §4.3: 地平ごとの持続と距離
```

`analyze_horizon.py` の既定の入力は `levels_clean.json`（短い窓の素材）。
`ISSUE449_SRC=long.json` を渡せば 52 日ぶんの素材でも動く。

## 何を測っているか

| スクリプト | 出す表 | 要点 |
|---|---|---|
| `probe_levels.py` | — | 価格水準の履歴と 1m ローソクを取る。**各水準は自分の時間足で 1 回だけ**取り、MTF 固定水準は投影しない（投影すると同じ値を最大 3 回計算する） |
| `analyze_horizon.py` | §4.3 | 地平（含める水準の時間足）ごとに「次のターゲット」の**指名の持続**と距離 |
| `analyze_reach.py` | §13 | **到達率・到達までの時間・反応**。反応は「別の時刻・同じ距離・水準から離れた価格」を対照に取る |

## 測定上の約束（崩すと結論が変わる）

- **周期標本を使う**（60 分ごと）。エピソード始端を標本にすると、新しい目標は価格の直近に
  現れるため到達率が過大になる（実測: 88〜96% → 78〜95%）。設計書 §13.5。
- **対照は距離を揃える**。`v ± (20〜60)` 点のようにずらすと距離差が反応差に混ざる。
  別の時刻で同じ距離を取る。
- **価格スケールでない系列を混ぜない**。`btlm_trail` は `beta` / `sigma` / `band_hit_rate` も
  返す。判定は名前ではなく**実値の桁**で行う（`probe_levels.py` の `10000 < mid < 200000`）。
- **行の識別子にパラメータを含める**。`MA` は 1 つの時間足に 3〜9 本あり、系列名だけでは
  衝突する。設計書 §11。
- 乱数は種を固定している（`analyze_reach.py`）。対照の抽出が実行ごとに変わらないようにするため。

## この測定で分かったこと（結論だけ・詳細は設計書）

- 到達率・到達までの時間は**距離で素直に決まる**（短期 11 点 95% 1 分 / 中期 87〜95 点 86% 16 分 /
  長期 277〜304 点 78〜84% 119〜122 分）。表示に添える情報として使える。
- **反応には水準としての情報が無い**。同じ距離の「水準でない価格」と有意差なし
  （差 −5.4 〜 +2.8pt・|z| ≤ 2.5・12 比較）。「水準に到達したら反発する」は支持されない。
- 「次のターゲット」の指名が変わる主因は**価格が通り過ぎること**ではなく、
  短い足の水準が動いて**割り込むこと**（短期 54% / 中期 60%）。

## 限界

1 銘柄（JP225）・52.1 日（2026-07-07 〜 2026-08-28 UTC）・テンプレート 1 設定のみ。
反応の定義は「先に X 点戻るか進むか」（X = 15 / 30）だけ。**一般化しない。**

## 追加（2026-08-29）: オシレータ水準 → 価格 の逆写像

`probe_inverse.py` / `probe_heatmap.py` は、第 2 表のオシレータ（`ma_marod` /
`btlm_trail_marod` / `profit_rsi`）の分位水準を**価格へ変換**して第 1 表のラダーへ
反映する設計の根拠を出す。参照実装（各指標の core）を**無改変で前進評価**するだけで、
逆関数の数式は書かない。

```bash
python3 probe_inverse.py    # 逆写像の形（区分メビウス）・単調性・変換後の距離
python3 probe_heatmap.py    # ラダー各行を分位段で塗る案の成立性と発行回数
```

`ISSUE449_ROOT` でワークスペース根を指定できる（既定は本ファイルから 3 つ上）。

### 分かったこと

- 現在バーの終値 `C` に対する指標値 `v(C)` は**区分メビウス** `(aC+b)/(C+d)` である。
  区分の境目は適用価格 hlc3 の折れ（走行 H / L）で、`profit_rsi` はさらに上下分岐
  （`x_t` が `x_{t-1}` を跨ぐ点）が加わる。当てはめ残差は **6e-14（marod）/
  4e-12（RSI）**。よって**逆写像は近似ではなく閉形式で厳密**。
- `v(C)` は全区分で**単調増加**。到達判定が価格の交差と同値になる条件を満たす。
- **1 instance あたり「区分数 × 3」回の前進評価**で係数が決まり、以後の価格評価は
  閉形式。ラダー 82 行の評価で発行 **0 回**（直接呼びなら 2,050 回）。閉形式と直接
  呼び出しの最大差 **1.1e-08**。
- 変換した水準は **145 本**（ma_marod 54 / btlm_trail_marod 48 / profit_rsi 43）。
  現在値からの距離は**中央 3,252 点**で、`|距離| <= 350` 点に入るのは **17 本（11.7%）**
  しかない。最大 279,253 点（RSI はメビウスの**極**を持ち、現在バーで到達しうる
  上限へ近づくと価格が発散する）。

## 追加（2026-08-29）: 第 2 表を連続量のヒートマップにできるか

`probe_continuous.py` / `probe_forming.py` は、第 2 表の段ラベル（帯内 / 上帯超 / ext 超…）を
廃して**連続量のヒートマップ**にする案の根拠を出す。候補の連続量は
**因果ローリング分位** `p ∈ [0,1]`（窓 = `values[t-window_n : t]`・当該バー除外＝
`common.marod_bands` と同一規約）。既存の水準はこの `p` のしきい値にすぎないので、
`p` は 4 指標・8 時間足を通じて**同一の意味**を持つ唯一の量である。

```bash
python3 probe_continuous.py   # M1 飽和 / M2 分布 / M3 裾の分解能
python3 probe_forming.py      # M4 形成中バーのバイアスと是正の検証
```

### 分かったこと

- **本体は一様**（M1/M2）。`1m`〜`1D` の全 4 指標で 10 分割ヒストグラムが各 8〜13%、
  `p=0` / `p=1` の張り付きは **2% 未満**。ラベル無しの連続配色で色域を使い切れる。
- **裾は飽和する**（M3）。正常帯 上端を超えたバーのうち **3〜30%**（`1M` は最大 50%）が
  `p = 1.0` に張り付き、「わずかに超えた」と「極端」を区別できない。
  既存の POT/GPD 水準はまさにここを解像するために在る。
- **`1M` は劣化する**。バー 169 本に対し窓 260 本で窓が埋まらず、`p=1` が 9.5%、
  最下位ビンが空になる。
- **形成中バーのバイアスは tickvol 固有で決定的**（M4-a）。tick 数は足の中で積み上がる量
  なので、確定足の分布へ当てると経過割合 `f` が小さいうちは必ず極小に出る。
  `1h` の中央値は **f=0.1 / 0.2 で p = 0.000**、f=0.3 で 0.004、f=0.5 で 0.065。
  確定足だけの基準は 0.392（M4-b）。**1 時間の前半はいつでも最も冷たい色**になる。
- **是正は効く**（M4-d）。部分足を「**同じ経過割合の部分足の分布**」へ当てると、
  中央値は f に依らず平坦になる（5m 0.480〜0.484 / 15m 0.454〜0.468 / 1h 0.383〜0.396）。
  確定足の基準値と一致し、バイアスは消える。比較集合を揃えるだけで、
  足内の tick 到来プロファイルを仮定しない。

### 限界

1 銘柄（JP225）・1m 50,000 本（52.1 日）・テンプレート 1 設定のみ。M4 は 1m から
部分足を再構成できる `5m` / `15m` / `1h` に限る（`4h` 以上は窓 500 本に足りない）。

### 裾の目盛り（`probe_tailscale.py`・M5）

帯外の目盛りを既存の POT/GPD で与える案を測った。`common.gpd` を無改変で使い、
エピソード畳み込み・`k_events=50`・`MIN_GPD_EVENTS=30` の既存規約に従う。

```
帯内 : p = 経験順位（当該バー除外の因果ローリング分位）        ∈ [0, q_high]
帯外 : p = q_high + (1 - q_high) * F_GPD(v - u ; xi, beta)     ∈ (q_high, 1]
```

```bash
ISSUE449_ROOT=/path/to/workspace python3 probe_tailscale.py
```

- **当てはまるときは完全に効く**。`p = 1.0` の張り付きが **3〜50% → 0.0%**（全 33 セル）。
  相異値は 10〜122 → **64〜2,399** へ増える。
- **接合は連続**。帯直上での跳びは **0.0000〜0.0031**（目盛り全幅の 0.31% 以下）。
  単調性は構成上成立（`F_GPD` は超過分について単調増加）。
- **有限終端の超過は無視できる**（`xi < 0` のとき。実測 **0.0〜1.0%**）。
- **ただし当てはめられないことが多い**。観測 30 件（`MIN_GPD_EVENTS`）未満で
  GPD を出せないバーの割合は **4.6%〜100%**。**33 セル中 12 セルは 100%**
  （`1h`/`4h` の marod 2 種・`1D` の `btlm_trail_marod`・`1W` の 3 種・`1M` の 4 種）、
  さらに 6 セルが 50% 超。上位足は履歴内にエピソードが 30 件たまらない。
- `MIN_GPD_EVENTS` を下げる案は採らない。`levels.py` ③ の実測どおり 30 未満では
  推定量の変動係数が 0.71〜0.95（自身の値と同じ大きさで揺れる）になるため。
