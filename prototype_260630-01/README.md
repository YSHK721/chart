# Market Profile 試作（TPO 時間累積ヒートマップ）  prototype_260630-01

ブランチ: `feature/prototype-market-profile` ／ データ: `prototype_260626-01/data.json`（読み取り専用）

## 目的
チャート上で **Market Profile** を確認できる試作。価格帯ごとに「価格がそこに滞在した時間の累積（TPO）」を
横ヒストグラムで表し、**累積が多い帯ほど赤**（青=低→赤=高のヒート）で視覚的に判断できるようにする。

## 仕様（確定）
1. **TPO（時間累積）**: 価格レンジを N_BINS 等分。時間単位足（既定=日足1本）の `[low, high]` が跨ぐ
   各ビンに +1。= 「その価格帯で値が付いた期間数」。
2. **カラースキーム**: 連続ヒート（turbo）。TPO 最小→青、最大→**赤**。POC は最濃赤。
3. **POC（Point of Control）**: TPO 最大の価格帯（最も時間が集中＝市場の合意価格）。
4. **バリューエリア（VA）**: POC から TPO 降順にビンを集め、累積が総TPOの **70%** に達する価格範囲（VAL〜VAH）。
5. **チャート連動**: ローソク足と価格軸(y)を共有し、右に横ヒストグラムを並置。POC/VA を両図に線・帯で明示。
6. **判定補助**: 現値が VA 上（割高側）/ VA 内（均衡）/ VA 下（割安側）を表示。

## 設定（`market_profile.py` 冒頭 CONFIG）
| 項目 | 既定 | 説明 |
|---|---|---|
| `DISPLAY_TF` | `1D` | ローソク表示の足 |
| `TPO_TF` | `1D` | 時間累積の単位足（`4h` で細かい時間分解能） |
| `WINDOW_BARS` | `120` | 対象範囲（直近本数） |
| `N_BINS` | `60` | 価格ビン |
| `VA_PCT` | `0.70` | バリューエリア割合 |
| `CMAP` | `turbo` | ヒートのカラーマップ |

## 出力
- `out/market_profile.png` … ローソク＋TPOヒート＋POC/VA
- `out/market_profile.json` … POC/VA/各ビンのTPO（再利用・UI連携用）

## 実行
```bash
python3 prototype_260630-01/market_profile.py
```

## 設計判断
- **時間単位＝足1本**: 日足では「価格がその帯で値を付けた日数」。古典的TPO（30分レター）の日足版。
  より細かくしたい場合は `TPO_TF=4h`（22,750本）でビン滞在を高分解能化。出来高加重ではなく**時間**ベース。
- **VA=70%**: 標準的なMarket Profileの定義に準拠。
- **静的レンダ（現フェーズ）**: rapid-prototype として「動く証拠」を最短で得るため matplotlib。

## インタラクティブWeb版（実装済み A/B/C）
起動:
```bash
python3 prototype_260630-01/mp_server.py 8810   # → http://localhost:8810
python3 prototype_260630-01/verify.py 8810      # playwright スクショ → out/web_shot*.png
```
- **A: Web対話** … lightweight-charts v5 のローソクに、`priceToCoordinate` で価格整列した
  canvas オーバーレイの TPO ヒートを重畳。上部UIで tf/n/bins/src/VA%/sessions を変更→再計算。
  ファイル: `mp_server.py`（API）, `mp_core.py`（TPO計算）, `web/index.html`, `web/js/app.js`。
- **B: ティックベース集計（既定）** … `src=dwell` で **価格帯の滞在時間（秒）を原子**に集計。
  表示足(tf)に依らず常に実ティック(per-day parquet, `contact_scan/tick_window`)から、
  各ティックの「次ティックまでの経過秒」のうち**アクティブ時間に重なる秒数だけ**を価格帯へ積算
  （**セッション認識方式**）。休場帯（週末・日次メンテ）は (曜日×時) のティック密度から自動抽出し除外。
  - 休場マスク: (7曜日×24時)バケットのティック数が ピーク×`ACTIVE_FRAC`(=0.10) 未満を「休場」と判定。
    実データから JP225 のセッション（土曜全休／日曜22時UTC再開〜金曜21時閉場／日次メンテ20-22時UTC）を
    自動復元。ブローカー個別カレンダー不要。
  - 効果: 取引中の静かな滞在（17〜数百秒）は満額残しつつ、休場・薄商い帯を厳密除外（17秒問題も解消）。
    POC/VA はギャップ処理にほぼ不感（実測で不動）＝主目的は総滞在秒の正確さと日中分析の布石。
  これが真の time-at-price。比較用に `src=m1`(1ティック=1カウント)・`1D/4h`(足レンジ+1) も選択可。
  - 例: dwell の POC は「実時間で最も滞在した価格帯」、tick数の POC は「最もティックが多い(活発な)価格帯」で**別物**。
  - 性能: 120日 約6.6s / 30日 約2s（per-day parquet 読み込み）。
- **C: 日次プロファイル（スプリット）** … `sessions` トグルで**各営業日の実プロファイル形（横ヒストグラム）を
  その日の位置にオーバーレイ**（ローソクを減光背景化＝本来のTPO表示）。応答 `sessions:[{date, tpo:[表示bin値]}]`。各日は日内スケールで
  正規化して形を表示。n を小さくするほど各日が広く見やすい。

### 表示の調整
- **ヒートの重なり回避**: ローソクを左へ寄せ、右 `PROFILE_FRAC`(=30%) をプロファイル専用余白に分離。
- **全幅ヒートグラデーション**: 価格帯ごとに基準不透明度 `HEAT_BG_BASE`(=3%)＋TPO比例 `HEAT_BG_GRAD`(=15%)
  の薄い帯を全幅に敷き、チャート背景でも価格帯の時間集中を判読可能（赤=多い）。

### 過去に遡る（時間カーソル・as-seen-at-t）
- ヘッダの **「リプレイ」** ON ＋ **スライダ/チャート横スワイプ** で時点T を過去へ移動 → **その当時の累積プロファイル**を表示。
  日別ロールアップの合算なので**未来リーク無し**（T以前の日だけ加算）＋キャッシュで**スクラブが即時**。
- **AB兼用**（モード切替）:
  - **アンカー**: 窓の起点〜T を積み上げ（“当時の累積”そのもの。遡るほどバーが痩せる）。
  - **ローリング**: T直前 `ROLL_BARS`(=60本) のローリング窓。
- **スナップショット**（既定OFF）: チェックON で「その当時の見え方」モードに。
  - ローソクをTまでに切る（当時の見え方）＋ **当日以外の累積バーを減光**（`DIM_ALPHA`）し **当日分を明るく強調**。
  - OFF時は通常の明るい累積プロファイル（視認性優先）。当日強調はスナップショットONに紐付け（専用チェックは設けない）。
  - 当日バーは当日データを当日内スケールで表示（累積合計ではない）。API `?today=1` で `today[]`/`today_max`。

### 期間範囲選択（ドラッグ / ダブルクリック）
- 起動方法は2通り:
  - **ダブルクリック（macOSのダブルタップ含む）** でアーム → 横ドラッグで範囲 → 離すと**自動で通常操作に復帰**。
  - ヘッダの **「範囲選択」** トグル ON → 横ドラッグ（複数回選択したい時向け）。
- 選択した期間だけで TPO を再計算。選択中はチャートのスクロール/ズームを停止（横ドラッグの衝突回避）、
  選択帯を青破線で表示。**「全体」** で全期間に復帰。
- macОS 補足: トラックパッドのドラッグ（クリックドラッグ/タップ＆ハーフ/3本指ドラッグ）は標準マウス
  イベントに変換され、そのまま動作。`dblclick` も標準対応。フォースタッチ等の真のOSジェスチャは
  ブラウザに公開されないため非対応。
- 内部: ドラッグ pixel → `timeScale.coordinateToLogical` → 足の time → `/profile?from=&to=`。
  `handleScale.axisDoubleClickReset:false` でチャート既定のダブルクリック挙動を無効化し選択に転用。

### API
- `GET /candles?tf=1D&n=120`
- `GET /profile?tf=1D&n=120&bins=60&src=dwell|m1|1D|4h&va=0.70&sessions=0|1[&from=<sec>&to=<sec>][&barw=<pt>]`
  - `src=dwell`(既定) … 原子=tick滞在秒（真の time-at-price）。`m1`=tick数、`1D/4h`=足レンジ+1。
  - `from`/`to` … 期間範囲選択（任意・UNIX秒）。指定時はその区間に限定して集計。
  - `barw` … **バーのレンジ（1バーの価格幅 pt）を直接指定**。指定時は `n_bins=round(窓幅/barw)` を算出し `bins` に優先。
    UIの「range」セレクタ（auto/25/50/100/250/500pt）に対応。応答に実効 `bar_width`(pt) を含む。
  - 応答に `atom`（"tick滞在秒"/"tick数"/"1D足レンジ" 等）と `tpo_units`（滞在秒総和 or 本数）を含む。

### 性能（AB兼用: 日別ロールアップ + メモリキャッシュ）
- ティックベース集計は **固定10ptグリッド(`GRID_W`)で日別に集計→メモリキャッシュ→窓合算→表示binへ再集計**。
- 初回に見た日だけ parquet 読込＋日別集計（1日ぶん）。以降は **bins/VA/sessions/範囲選択/別窓/原子切替すべて約1ms**。
  - 実測(HTTP): 初回 3.1s（休場マスク構築＋30日ロールアップ）→ 2回目 1.0ms／bins変更 0.8ms／m1切替 0.7ms。
- 日別 dwell はその日のティックで自己完結（日跨ぎ休場ギャップは自然に除外）。総滞在は連続計算比 約1%差
  （日境界ギャップの近似）だが **POC/VA/形は直接計算と完全一致**（検証済み）。
- 窓は表示足の全期間（最終日を含む）を集計。※旧実装は最終日を除外していたため POC が変わる場合あり（修正）。
