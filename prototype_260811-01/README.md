# prototype_260811-01 — 口座状態エンジン（証拠金・ロスカットの参照実装／ISSUE-369）

発注計画（方向・建値・ロット・損切り・利確）を **実 tick（bid/ask）へ順に適用**し、決済までの
口座状態（残高・有効証拠金・必要証拠金・証拠金維持率）とイベント（約定・損切り・利確・
ロスカット）をティック粒度で再現する。本プロトタイプが **OANDA 証券 JP225 CFD の証拠金・
ロスカット計算の参照実装（権威）**であり、ポジションサイズ計算機
（`integrated_position_sizing_calculator.html`）と将来のチャート統合（ISSUE-368）の式は
ここの実測へ一致させる。

## アクター構成（SRP）

| アクター | ファイル | 責務 |
|---|---|---|
| 口座状態エンジン | `account_engine.py` | 口座状態の計算のみ（標準ライブラリのみ・データ読込もレポートも持たない） |
| レポート提示 | `report_build.py` | 状態時系列 JSON → グラフ入り単体 HTML（計算しない・サーバ不要） |
| データ供給 | `run_scenario.py` | 発注計画 JSON ＋ 期間 → `marketdata.tick_m1`（tick tree レイアウト単一権威）で tick を読みエンジンへ流す CLI |
| 式の検定 | `verify.py` | 現行 HTML の静的式とエンジン実測の数値突き合わせ |

## 使い方

```bash
VENV=/workspaces/app/lightweight-charts-python-main/.venv/bin/python
export MARKETDATA_DATA_DIR=/workspaces/app/data/marketdata   # worktree から実行する場合

# 1) シナリオ実行（発注計画 → 口座状態時系列 JSON）
$VENV run_scenario.py --plan plans/long_stop.json --start 2026-08-06 --end 2026-08-06 \
    --out out/long_stop.json --sample 20

# 2) レポート生成（ブラウザで開くだけの単体 HTML）
$VENV report_build.py --in out/long_stop.json --out out/long_stop.html --title "ロング・損切り到達"

# 3) 式の検定
$VENV verify.py
```

発注計画 JSON の形式は `run_scenario.py` の docstring 参照（`plans/` に代表 4 シナリオ）。

## 口座モデル（実装済みの前提）

- 必要証拠金 ＝ 時価 × 数量 × V × 証拠金率（既定 10%）。**時価ベースで毎 tick 変動**。
- 有効証拠金 ＝ 口座残高 ＋ 評価損益。評価価格はロング＝bid／ショート＝ask。
- 証拠金維持率 ＝ 有効証拠金 ÷ 必要証拠金。**100% 以下でロスカット**（株価指数 CFD に
  マージンコールは無い）。損失最大の建玉から成行決済し、1 建玉ごとに再評価。
- 指値は指値価格で約定（ロング: ask≤price ／ ショート: bid≥price 到達時）。
  成行は当該 tick のロング＝ask／ショート＝bid。

## 確定した式（実測 2026-08-11・verify.py 全 6 検定合格）

1. **代数同値（V1）**: 計算機 HTML の 2 段式 `lcDist = (E−reqMargin)/U × 1/(1∓mr)` は
   閉形式 **X = (avgP ∓ E/U) / (1 ∓ mr)**（ロング −／ショート ＋）と同値（最大差 2.9e-11）。
2. **ロスカット価格（V2/V3）**: 実 tick でのロスカット発動価格は閉形式 X と一致。
   - ロング（2026-08-06・25 単位・E=172,000）: X=65,151.70 に対し実測 65,151.37（差 −0.34pt）
   - ショート（2026-08-10・同）: X=66,409.42 に対し実測 66,410.53（差 +1.11pt）
   - 差はいずれも tick 間ギャップ由来（X を最初に跨いだ tick の評価価格で成行）。
     **HTML の mFactor（時価連動補正）は正しい**。
3. **U1 の感度（V4）**: 必要証拠金の時価を mid にしても trade-side（bid/ask）にしても、
   ロスカットのトリガー価格差は 0.0pt（現行スプレッド幅では実務影響なし）。
4. **必要証拠金（V5）**: 約定 tick では HTML 式（建値ベース）と実測が一致（差 −5.17 円＝
   スプレッド起源）。保有中は時価で **0.9% 変動**（HTML 式は発注時スナップショットと解せば正確）。

## 未検証事項（推測で断定しない）

- **[U1]** 必要証拠金の「時価」が bid/ask/mid のどれかは公式資料で未確認（既定 mid・
  `mark_price_mode` で切替可能。V4 で実務影響 0.0pt を確認済み）。
- **[U2]** ロスカット執行が「損失最大の建玉から 1 本ずつ決済→再評価」か「一括」かは未確認
  （単一建玉の検定には影響しない。複数建玉の部分決済順は公式確認が要る）。
- **[U3]** 損切り・ロスカットの約定価格はトリガー tick の評価価格（成行）。実際の板・
  スリッページは未反映（急変時に式どおりの約定は保証されない点は計算機 HTML と同じ前提）。
- **[U4]** 同一 tick で損切りとロスカットが同時成立した場合は損切り先行と仮定。
