## 1. アクセス制御の不備（OWASP A01:2025）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10:2025 で発生率第 1 位を維持。テスト対象アプリケーションの平均 3.73% に当該カテゴリの 40 CWE のいずれかが検出される。SSRF（旧 A10:2021）が本カテゴリに統合された |
| 必須対策 | ゼロトラスト原則：すべてのリクエストを認証・認可する |
| 必須対策 | API 認可：REST/GraphQL エンドポイント単位で細粒度の認可制御を実装する |
| 必須対策 | 動的権限評価：ユーザーコンテキストに応じた実行時権限チェックを実装する |
| 必須対策 | セッション管理：JWT トークンの署名検証と有効期限（最大 24 時間）を強制する |
| 必須対策 | SSRF 防御：外部 URL 取得時はホワイトリスト方式でアクセス先を制限する |

## 2. セキュリティ設定不備（OWASP A02:2025、新規上位ランクイン）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10:2025 で第 5 位（2021）から第 2 位に上昇。クラウドネイティブ環境での設定誤りが主要な要因として確認された |
| 必須対策 | 既定設定変更：管理者アカウント・サンプルアカウントの既定パスワードを必ず変更する |
| 必須対策 | 不要機能の無効化：未使用のポート・サービス・機能・アカウントを無効化する |
| 必須対策 | エラー処理：本番環境ではスタックトレース・内部パスをユーザーに返さない |
| 必須対策 | クラウド設定監査：S3 バケット公開・IAM 権限過大付与を CSPM ツールで継続検出する |
| 必須対策 | セキュリティヘッダ：CSP・HSTS・X-Frame-Options・X-Content-Type-Options を全レスポンスに設定する |

## 3. ソフトウェアサプライチェーン障害（OWASP A03:2025、新規カテゴリ）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10:2025 で新規独立カテゴリとして追加。Verizon DBIR 2025：第三者経由の侵害が 30%（前年 15% から倍増）。Sonatype：2025 年に 454,648 件の悪性パッケージを新規検出（99% が npm 上）。自己複製型 npm マルウェア「Shai-Hulud」が 2025 年に初確認された |
| 必須対策 | SBOM 生成：CycloneDX または SPDX 形式で全依存関係を可視化する |
| 必須対策 | 多段階検証：自動 SCA スキャン、手動レビュー、専門家評価の 3 段階を実施する |
| 必須対策 | サプライヤー評価：依存パッケージのメンテナ活動度・署名（Sigstore 等）の有無を確認する |
| 必須対策 | npm 警戒：postinstall スクリプト実行を CI で禁止し、自己複製型ワームの伝播経路を遮断する |
| 必須対策 | インシデント対応：依存パッケージの脆弱性公開から 72 時間以内にパッチ適用または代替する |
| 必須対策 | 高 CVSS 監視：Maven Central リリースの 40%・NuGet リリースの 39% が CVSS 9.0 以上の脆弱性を含むため、本番投入前に CVSS スコアを確認する |

## 4. 暗号化の失敗（OWASP A04:2025）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10:2025 で第 2 位（2021）から第 4 位に変動。Verizon DBIR 2025：盗難クレデンシャルが侵害の初期侵入経路の 22% を占め、暗号化・鍵管理の不備が要因として継続検出される |
| 必須対策 | 通信暗号化：TLS 1.3 を採用し、TLS 1.1 以前の利用を禁止する |
| 必須対策 | データ暗号化：AES-256-GCM または ChaCha20-Poly1305 を採用する |
| 必須対策 | 鍵管理：AWS KMS、Azure Key Vault、HashiCorp Vault のいずれかで集中管理する |
| 必須対策 | 証明書管理：自動更新を設定し、有効期限切れの 30 日前にローテーションする |
| 必須対策 | パスワードハッシュ：Argon2id または bcrypt（cost ≥ 12）を使用し、MD5・SHA-1 を禁止する |

## 5. インジェクション攻撃（OWASP A05:2025）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10:2025 で第 3 位（2021）から第 5 位へ変動。攻撃手法は引き続き多様化し、API・GraphQL での入力検証不備が主要な検出パターンとなる |
| 必須対策 | SQL：パラメータ化クエリまたは ORM のプリペアドステートメントを必ず使用する |
| 必須対策 | NoSQL/Graph：MongoDB・Neo4j 等の対応ドライバの安全な API を使用する |
| 必須対策 | XSS：Content Security Policy（CSP）ヘッダを設定し、`unsafe-inline` を禁止する |
| 必須対策 | 入力検証：言語標準のバリデーションライブラリで型・範囲・フォーマットを検証する |
| 必須対策 | コマンドインジェクション：`shell=True` 相当の API を禁止し、引数を配列で渡す |

## 6. 脆弱性悪用とエッジ機器（Verizon DBIR 2025 新興パターン）

| 項目 | 内容 |
|---|---|
| 実証根拠 | Verizon DBIR 2025：脆弱性悪用が初期侵入経路として 20% に増加（前年比 +34%）。エッジ機器・VPN への悪用が 22% を占め、2024 年の 3% から約 8 倍に拡大した |
| 必須対策 | パッチ適用：CISA KEV カタログ掲載の脆弱性は公開後 14 日以内にパッチを適用する |
| 必須対策 | エッジ機器：VPN・ファイアウォール・ロードバランサのファームウェアを月次で更新する |
| 必須対策 | 公開資産棚卸し：外部公開資産の一覧を ASM ツールで継続的に更新する |
| 必須対策 | ランサムウェア対策：Verizon DBIR 2025 で侵害の 44% に出現するため、オフラインバックアップを保持する |

## 7. AI/ML セキュリティ（OWASP Top 10 for LLM Applications 2025）

| 項目 | 内容 |
|---|---|
| 実証根拠 | OWASP Top 10 for LLM Applications 2025：LLM01 プロンプトインジェクションが第 1 位。Verizon DBIR 2025：従業員の 15% が業務端末から GenAI システムに常時接続し、うち 72% が非企業メールアドレスで利用する |
| 必須対策 | LLM01 プロンプトインジェクション：LLM への入力を構造化し、システムプロンプトと分離する |
| 必須対策 | LLM02 機密情報漏洩：LLM 応答に PII・API キー・社外秘情報が含まれないよう出力フィルタを設定する |
| 必須対策 | LLM03 サプライチェーン：使用モデルのハッシュ値または署名を検証する |
| 必須対策 | LLM04 データ・モデル汚染：学習データに機密情報・敵対的サンプルが混入しないよう前処理で除去する |
| 必須対策 | LLM05 出力処理不備：LLM 出力をシステムコール・SQL・シェルに直接渡さず、必ず検証層を挟む |
| 必須対策 | LLM06 過剰なエージェンシ：LLM 起動の自律アクション（ツール実行・関数呼出）に最小権限を適用する |
| 必須対策 | LLM07 システムプロンプト漏洩：システムプロンプトに機密値・認可ロジックを埋め込まない |
| 必須対策 | LLM08 ベクトル/埋込脆弱性：RAG ベクトル DB へのテナント分離を実装する |
| 必須対策 | LLM09 誤情報：LLM 出力を一次情報源として扱わず、業務判断には必ず人間レビューを介在させる |
| 必須対策 | LLM10 リソース枯渇：トークン数・呼出頻度・コストに上限値を設定する |
| 必須対策 | AI 生成コード：人間によるレビューを必須プロセスとして組み込む |
