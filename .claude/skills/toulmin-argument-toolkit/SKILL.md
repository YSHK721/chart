# 目的

論証を 6 要素に分解し構造検証する。

## §0. 仮説と事実の区別

| 区分 | 取り扱い | 表記 |
|---|---|---|
| Toulmin 原典定義（事実） | そのまま採用する | 出典なしで断定する |
| 入力文書からの抽出（事実） | 原文引用付きで提示する | 「原文より」と明示する |
| 推測・補完（仮説） | 採用は任意。根拠を併記する | 「（推測）」と明示する |
| 不明 | TBD として未解決事項に記録する | 「TBD: 確認要」と明示する |

## §1. 定義

トゥールミン論証構造（Claim / Data / Warrant / Backing / Qualifier / Rebuttal の 6 要素）に基づき、論証の (A) 構築 / (B) 分析 / (C) 校正 を統合的に支援するスキル。一次出典：Toulmin, S. (1958/2003) *The Uses of Argument*, Cambridge University Press。

## §2. 原理原則

- Toulmin が定義した 6 要素以外の要素を独自に追加しない
- 形式論理学（三段論法・記号論理）の枠組みで実質的議論を評価しない
- 領域依存性（科学／法／倫理／日常会話）を意識し、裏付けの基準を一律化しない
- 推測と事実を必ず分離し、推測には「（推測）」マーカーを付与する
- 分析的議論（トートロジー）と実質的議論を混同しない

## §3. 用語定義

| 用語 | 定義 |
|---|---|
| C / Claim / 主張 | 議論の結論として正当化される命題 |
| D / Data / データ | 主張を支える具体的事実・統計・事例 |
| W / Warrant / 保証 | データから主張への移行を許可する一般原則 |
| B / Backing / 裏付け | 保証の権威・信用を支える理論・実績 |
| Q / Qualifier / 限定子 | 主張の強さ・確実性を示す語 |
| R / Rebuttal / 反駁 | 保証が適用されない例外的状況 |
| 構築モード | 未整理の主張・データを 6 要素に整理する処理 |
| 分析モード | 既存文章から 6 要素を抽出し弱点を診断する処理 |
| 校正モード | 既存論証文章の論理的整合性を診断し改善提案する処理 |
| 分析的議論 | 結論が前提の言い換えで新情報を生まない論証 |
| 実質的議論 | 結論が前提を超えて新情報を含む論証 |

## §4. 強制ルール

| ルール | 内容 |
|---|---|
| 改変禁止 | 入力文書の原文を改変しない。校正は構造診断と改善提案に留める |
| 主観禁止 | 「良い論証」「優れた主張」等の感想・印象は出力しない |
| 6 要素逸脱禁止 | Toulmin が定義した 6 要素以外の要素を勝手に追加しない |
| 推測明示 | 推定で補完した要素は「（推測）」と明示する |
| 出典付き | 入力文書から抽出した要素には原文の該当箇所を併記する |
| 限定子の過剰断定検出 | 「常に」「すべて」「絶対に」等の絶対表現は警告対象とする |
| 領域依存性の認識 | 裏付けの基準は議論領域（科学・法・倫理等）で異なる前提で判定する |
| 曖昧表現禁止 | 「適切に」「効率的に」「一般的に」等の曖昧語を使用しない |
| 思考代替防止 | 各 step の「手順」は必ず「判定基準」と併記する。手順単独記述を禁止する（D1）|
| 判定基準優先 | 各 step で「手順」と「判定基準」が衝突した場合は判定基準を優先する。手順への機械的従属を禁止する（D10）|

## §5. 実行プロセス

§5 intro：本章の各 step は「判定基準」が「手順」を原理的に拘束する（思考代替リスク防御 D1）。手順単独の機械的踏襲は §4 強制ルールで禁止される。要素判定が困難な場合のみ `references/toulmin-6-elements.md` を、限定子・反駁の選定で迷う場合のみ `references/qualifier-rebuttal-patterns.md` を、議論種別の判定が必要な場合のみ `references/analytic-vs-substantial.md` を読み込む。

### step S-1: モード判定

- **判定基準**：入力形式から (a) 未整理アイデア／結論素案＋根拠列挙 → 構築 / (b) 完成された文章（論文・記事・ブログ）＋抽出要求 → 分析 / (c) 既存論証文章＋論理整合性診断要求 → 校正 を識別。判定不能時のみユーザーに 3 択で確認する。
- **出力先**：output.md §1（モード判定結果）
- **アンチパターン**：複数モードを同時起動して 6 要素を二重生成する

### step S-2: 6 要素抽出または設計

- **判定基準**：構築モード＝要素を順次設計、分析モード＝原文から抽出、校正モード＝既存論証から逆抽出。明示なしの要素は「（推測）」または「欠落」を選択し事実と区別する。
- **出力先**：output.md §2（6 要素テーブル）
- **アンチパターン**：保証 (W) を推測で埋めた事実を明示せず断定する
- **手順**：
  1. C (Claim) 特定：結論文を 1〜2 文に整形（複数主張は階層化）
  2. D (Data) 抽出：根拠を箇条書きで列挙し各出典・確実性を併記
  3. W (Warrant) 同定：明示なら原文引用、推測なら「（推測）」付与
  4. B (Backing) 探索：保証の権威根拠を探索、なければ「欠落」と記録
  5. Q / R 抽出：限定語と例外条件を保全、なければ「欠落」と記録

### step S-3: 強度評価または弱点診断

- **判定基準**：構築モード＝5 観点強度評価（データ信頼性／保証妥当性／裏付け権威性／限定子適合性／反駁網羅性）、分析モード＝5 型弱点パターン照合（保証欠落／裏付け不足／限定過剰／反駁未検討／分析実質混同）、校正モード＝3 観点診断（主張根拠接続／段落間接続／論旨一貫性）。
- **出力先**：output.md §3（診断テーブル）
- **アンチパターン**：限定子の過剰断定（「常に」「すべて」「絶対に」）を警告せず通過させる
- **手順**：
  1. モードに応じた診断観点リストを選択
  2. 該当箇所を原文引用付きで列挙
  3. 深刻度ラベル（🔴 CRITICAL ／ 🟡 WARNING ／ 🔵 INFO）を付与

### step S-4: 改善提案

- **判定基準**：構築モード＝6 要素を組み込んだ文章化案、分析モード＝指摘ごとの補強示唆（何を補えば論証が強化されるか）、校正モード＝原文引用＋問題種別＋欠落要素＋修正後の具体的記述。書き直しではなく構造改善示唆に留める。
- **出力先**：output.md §4（改善提案）
- **アンチパターン**：原文を勝手に書き換えてユーザー意思を奪う ／ 改善案を主観表現で記述する

### step S-5: ステップ完了判定（思考代替リスク防御 D6）

各 step の手順完了後、次 step 進行前に以下を検証する。

- [ ] 判定基準への回答が出力に含まれているか
- [ ] 推測要素が「（推測）」マーカー付きで事実と分離されているか
- [ ] 入力前提（モード判定結果）と矛盾する結果が出ていないか
- [ ] 出力が次 step の入力として整合するか

充足しない場合：手順を機械的に再実行せず、判定基準に立ち返り別経路を検討する。最大 3 回再試行、3 回失敗時は §6 異常時出力で中断報告する。

## §6. 結果出力

1. `${CLAUDE_SKILL_DIR}/output.md` に記載されたテンプレート構造（モード判定結果に応じた §A／§B／§C のいずれか）に従って出力する
2. 異常時（S-5 完了判定 3 回失敗）は以下フォーマットで中断報告する：

```
【中断報告】
失敗 step：S-{連番}
判定基準充足失敗観点：[該当チェック項目]
収集済み要素：[途中までの 6 要素抽出結果]
TBD：[ユーザー確認が必要な事項]
```
