# 目的

シンボル単位編集を Serena で統制する

## §1. 定義

コード編集・解析タスクにおいて、ファイル全体置換ではなくシンボル単位（関数・クラス・メソッド・変数・モジュール）の精緻な追加・修正・削除・参照を Serena MCP のツール経由で実行することを保証する規律スキル。シンボル単位操作の優先・副作用ツールの事前確認・MCP 障害時の標準ツールへのフォールバックを規定する。

## §2. 原理原則

- シンボル単位の編集・解析が可能な場合、`str_replace` 等の汎用テキスト編集ではなく Serena MCP のシンボル操作ツールを優先する
- コード状態を変更する副作用ツールは、実行前にユーザーの明示的承認を得る
- Serena MCP が利用不可となった場合は、フォールバック理由とフォールバック先ツール名を併記してユーザーへ報告する

## §3. 用語定義

| 用語 | 定義 |
|---|---|
| シンボル | 言語サーバーで識別される関数・クラス・メソッド・変数・モジュール等の構造単位 |
| クエリ系ツール | コード状態を変更しない読み取り専用ツール（`find_symbol` / `get_symbols_overview` / `find_referencing_symbols` / `read_file` 等） |
| 副作用ツール | コード・メモリ・プロジェクト状態を変更するツール（`replace_symbol_body` / `rename_symbol` / `insert_after_symbol` / `insert_before_symbol` / `safe_delete_symbol` / `replace_content` / `create_text_file` / `write_memory` / `edit_memory` / `delete_memory` / `rename_memory` / `activate_project` / `onboarding` / `execute_shell_command`） |
| フォールバック | Serena MCP 呼び出し失敗時に、標準ツール（`view` / `str_replace` / `bash_tool` 等）へ切り替える退避動作 |
| 一過性失敗 | タイムアウト・接続切れ等、再試行で解消しうる失敗 |
| 恒常的失敗 | ツール未登録・プロジェクト未アクティブ等、再試行で解消しない失敗 |

## §4. 強制ルール

| ルール | 内容 |
|---|---|
| 改変禁止 | 指示以外の改変は絶対に禁止する |
| 主観禁止 | 主観・感想・印象の出力は絶対に禁止する |
| シンボル操作必須 | シンボル単位の追加・修正・削除・参照・解析は Serena MCP のツールで行う。汎用テキスト編集での代替を禁止する |
| 副作用前確認 | §3 で定義した副作用ツールの実行前にユーザー確認を取る。確認なしの実行を禁止する |
| フォールバック明示 | Serena MCP 不可時は「Serena MCP が <理由> により利用不可のため、標準ツール <ツール名> にフォールバックする」と報告する。無断フォールバックを禁止する |
| 再試行制限 | 一過性失敗は最大 1 回再試行する。恒常的失敗は再試行せずフォールバックへ移行する |

## §5. 実行プロセス

### step S-1: タスク種別判定

入力タスクが「シンボル単位編集・解析」「ファイル単位操作」「テキスト検索置換のみ」のいずれかを判定する。シンボル単位以外は本スキルの対象外として通常フローへ復帰する。

### step S-2: Serena ツール選択

シンボル単位タスクに対し、操作種別（検索／参照／概要取得／本体置換／挿入／リネーム／削除）に対応する Serena MCP ツールを選択する。クエリ系か副作用ツールかを区別する。

### step S-3: 副作用ツール事前確認

選択ツールが §3 副作用ツールに該当する場合、対象シンボル名・操作内容・期待される変更範囲をユーザーへ提示し、明示的承認を得る。承認が得られない場合は中断する。

### step S-4: ツール実行と失敗時フォールバック

選択ツールを実行する。失敗時は以下のフォールバック手順を適用する。

1. エラーを記録する：`[Serena エラー] ツール名: <name>, メッセージ: <message>`
2. 一過性／恒常的の判定：タイムアウト・接続切れは一過性、ツール未登録・プロジェクト未アクティブは恒常的
3. 一過性なら 1 回再試行、恒常的なら再試行せず手順 4 へ
4. 標準ツールへ切替：シンボル参照→`view` / `bash_tool`（grep / ripgrep）、ファイル編集→`str_replace` / `create_file`、コマンド実行→`bash_tool`
5. ユーザーへ報告：「Serena MCP が <理由> により利用不可のため、標準ツール <ツール名> にフォールバックする」

### step S-5: 完了基準検証

以下を満たすことを確認する。

- 当該タスクのシンボル単位操作のすべてが Serena MCP ツール経由で実施されているか、フォールバックの場合は理由と代替ツール名がユーザーへ報告されている
- 副作用ツール実行前にユーザー確認が取られている
- §6 に従い結果が出力されている

## §6. 結果出力

1. 実行したツール名・対象シンボル・操作種別・結果（成功／失敗）を提示する
2. フォールバック発生時は §5 step S-4 手順 5 のフォーマットで理由と代替ツールを併記する
3. 副作用ツール実行時は変更前後の差分または変更要約を提示する

## 効果減衰時の再呼び出し指針

会話の後続で標準ツールが無断使用されている場合、本スキルが自動コンパクションで失効した可能性がある（公式仕様：自動コンパクション時は各スキル最大 5,000 トークンまで保持、多数呼び出し時は古いスキルがドロップされる）。ユーザーは「Serena ツールを使って」等の自然言語で再判断を促すか、本スキルの再呼び出しを依頼すること。
