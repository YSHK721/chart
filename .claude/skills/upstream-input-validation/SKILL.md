# 目的

上流前提の追従を構造的に遮断する。

## §1. 定義

本スキルは「自分が出所でない判断」（= 上流入力）に内在する暗黙の前提を、判断確定の前に実コード grep / 型定義 Read / 既存仕様照合 / 公式仕様参照で実証する。「証拠不在の前提を所与として採用しない」を構造化することで、追従性バイアス（Type-B：上流向け追従）を遮断する。

本スキルの責務は「上流入力の前提検証」に限定する。「自分の成果物の論理整合性」検証は責務外（独立スキル `prompt-validation-workflow` が担当する設計）。両スキルは互いに参照せず独立して起動可能である。

## §2. 原理原則

- **上流入力 0 件時は本スキル不要**：依頼者指示・他者レビュー指摘・前段成果物・既存合意の引き継ぎがいずれも 0 件の場合は §5 step 1 で「該当なし」を明示し即時終了する
- **証拠先行**：判定（採用 / 棄却 / 条件付き採用）の確定よりも前に実証手段（grep コマンド・Read 対象パス・公式仕様参照箇所）を提示する
- **立証責任の非対称性**：上流入力への同意は実証的証拠が必須、上流入力への反論は前提への疑問の指摘で成立する
- **追従の不採用**：上流が Blocker / Critical 主張でも、引き継ぎ側の同意は独立した実証に基づく合意として扱う

## §3. 用語定義

| 用語 | 定義 |
|---|---|
| 上流入力 | 自エージェント・スキルが受領した依頼指示・他者レビュー指摘・前段成果物・既存合意の引き継ぎの総称。出所が自分でない判断のすべてを含む |
| 上流入力前提 | 上流入力に内在する「明示されていないが判断を支える事実主張」（型契約・ライブラリ仕様・既存 API 挙動・前段成果物の決定事項） |
| 実証手段 | grep（実コード）/ Read（型定義・仕様書）/ 公式仕様参照（バージョン明示）/ 該当 plan・ADR・commit 確認 のいずれか |
| 追従性バイアス Type-B | 上流（依頼者・他者レビュアー・前段成果物）の判断を所与として受容し、その前提を独自に検証しない失敗モード |

## §4. 強制ルール

| ルール | 内容 |
|---|---|
| 改変禁止 | 指示以外の改変は絶対に禁止する |
| 主観禁止 | 主観・感想・印象の出力は絶対に禁止する |
| 証拠先行 | 判定（採用 / 棄却 / 条件付き採用）の確定よりも前に実証手段を提示する。証拠を後付けする順序は禁止する |
| 立証責任の非対称性 | 上流入力への同意は実証的証拠の提示が必須。実証的証拠なき同意は「追従」として棄却する |
| 思考代替防止 | 各 step の「手順」は必ず「判定基準」と併記する。手順単独記述を禁止する（D1） |
| 判定基準優先 | 各 step で「手順」と「判定基準」が衝突した場合は判定基準を優先する。手順への機械的従属を禁止する（D10） |

## §5. 実行プロセス

5 step は順序付きサブ操作系列を構成し、前 step の出力が後 step の入力となる（step 1 で上流入力 0 件が確定した場合は step 5 にスキップする）。各 step の「手順」は判定基準と必ず併記し、手順単独の機械的踏襲を禁止する（思考代替リスク防御 D1）。

### step S-1：上流入力の整理

- **判定基準**：受領した入力のうち「自分が出所でない判断」を 4 種別（依頼者指示 / 他者レビュー指摘 / 前段成果物 / 既存合意の引き継ぎ）で分類する。4 種別すべて 0 件の場合は本スキル不要として step 5 にスキップする
- **出力先**：output.md §「上流入力の整理」
- **アンチパターン**：自分の出力と上流入力を混同し、自己出力起点の Pre-mortem を本スキルで実施する
- **手順**：(1) 受領入力を 4 種別で分類、(2) 各種別ごとに件数または「該当なし」を記録、(3) 4 種別すべて 0 件なら step 5 へスキップ宣言

### step S-2：前提抽出

- **判定基準**：各上流入力について「明示されていないが判断を支える事実主張」を抽出する。明示されている文言ではなく、その文言が成立するために必要な暗黙の前提を識別する
- **出力先**：output.md §「前提抽出」
- **アンチパターン**：明示されている文言のみを「前提」として記録し、暗黙の前提（型契約・ライブラリ仕様の挙動・既存 API の振る舞い）を見落とす
- **手順**：(1) 各上流入力の主張内容を 1 行で要約、(2) 主張が成立するために必要な事実主張を箇条書きで抽出、(3) 抽出した前提が独立検証可能か（実コード・型定義・公式仕様にアクセス可能か）を判定

### step S-3：証拠先行検証

- **判定基準**：各前提について実証手段（grep / Read / 公式仕様参照）を判定確定の前に提示し、実証コマンド・参照ファイル行番号・該当出力を記録する
- **出力先**：output.md §「証拠先行検証」
- **アンチパターン**：実証手段を提示せずに「採用 / 棄却」の判定を下す（証拠後付け）。または実証コマンドを記載するが該当出力を省略する（追跡不能）
- **手順**：(1) 各前提に対し実証手段を選択、(2) 実証コマンドを実行または該当ファイルを Read、(3) 出力結果を記録、(4) 実証取得 / 実証不可のいずれかを判定

### step S-4：判定

- **判定基準**：各上流入力について採用 / 棄却 / 条件付き採用のいずれかに分類する。立証責任の非対称性に従い、実証取得済の前提に基づくものは「採用」、前提崩壊が確認されたものは「棄却」、差し替え案で対応するものは「条件付き採用」とする
- **出力先**：output.md §「判定結果」
- **アンチパターン**：上流主張の重要度（Blocker / Critical / High）を批判的検証なしに継承する。または前提崩壊が確認された上流入力を「念のため採用」として通過させる
- **手順**：(1) step 3 の実証結果を上流入力ごとに集約、(2) 採用 / 棄却 / 条件付き採用のいずれに該当するかを判定基準に照らして決定、(3) 各分類について根拠（実証された前提・棄却された前提との関係）を記録

### step S-5：残存リスク特定

- **判定基準**：本タスクの範囲外で後続作業に委ねるべき項目を列挙する。該当がない場合は「なし」を明示する
- **出力先**：output.md §「残存リスク」
- **アンチパターン**：残存リスクを過剰に列挙し本工程の判定（step 4）を曖昧化する。または「なし」明示を省略する
- **手順**：(1) 本タスク範囲を確認、(2) 範囲外の検証必要事項を列挙、(3) 該当ゼロの場合は「なし」を明示

### ステップ完了判定（思考代替リスク防御 D6）

5 step の「手順」完了後、以下を検証してから本スキルの結果出力に進む：

- [ ] step 1 で上流入力 4 種別すべての分類結果（件数または「該当なし」）が記録されているか
- [ ] step 2 で各上流入力の前提が抽出され、独立検証可能性が判定されているか
- [ ] step 3 で各前提について実証コマンド・参照箇所・出力結果が記録されているか（証拠先行違反がないか）
- [ ] step 4 で各上流入力が採用 / 棄却 / 条件付き採用のいずれかに分類されているか
- [ ] step 4 で実証不可の前提を「採用」していないか（立証責任違反がないか）
- [ ] step 5 で残存リスクが列挙されている、または「なし」が明示されているか

充足しない場合：手順を機械的に再実行せず、判定基準に立ち返り別経路を検討する。最大 3 回再試行、3 回失敗時は呼び出し側エージェントに「上流入力検証 3 回連続失敗」を中断理由として返却する。

## §6. 結果出力

1. `${CLAUDE_SKILL_DIR}/output.md` に記載されたテンプレート構造に従って出力する
2. 上流入力 0 件の場合は output.md「上流入力なしのケース」例に従い「該当なし」を明示する
3. 上流入力 1 件以上の場合は output.md「上流入力ありのケース」例に従い 5 セクション（上流入力の整理 / 前提抽出 / 証拠先行検証 / 判定結果 / 残存リスク）すべてを出力する
