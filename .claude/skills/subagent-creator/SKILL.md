# 目的

公式準拠サブエージェントを生成・検証する

## §0. 仮説と事実の区別

| 区分 | 取り扱い | 表記 |
|---|---|---|
| 公式仕様（事実） | そのまま採用する | 出典なしで断定する |
| プロジェクト規約 | プロジェクト内で適用する | 「プロジェクト規約より」と明示する |
| 推奨（仮説） | 採用は任意。根拠を併記する | 「（推奨／仮説）」と明示する |
| 不明 | TBD として未解決事項に記録する | 「TBD: 確認要」と明示する |

## §1. 定義

Claude Code カスタムサブエージェント（`.claude/agents/<name>.md` または `~/.claude/agents/<name>.md` に配置される YAML frontmatter + Markdown 本文）の設計・新規作成・既存レビュー・委譲先選定を、公式仕様（`https://code.claude.com/docs/llms.txt` 配下のサブエージェント章）に厳密準拠して実施する。

サブエージェントとは、独立 context・ツール権限制限・概要のみ親会話に返却する委譲先である。本スキルは公式仕様外フィールドの混入と自動委譲不発火を構造的に防ぎ、最小権限の原則で動作する subagent 定義を生成または検証する。

## §2. 原理原則

- 公式仕様を一次出典とし、推測値・公式仕様外フィールドの生成を禁止する
- description は自動委譲発火条件として動詞ベース・トリガー列挙形式で記述する
- ツール権限は最小権限の原則に従い `tools` または `disallowedTools` で明示する
- サブエージェントはネスト不可・独立 context・概要返却の構造的制約を持つ
- 委譲先選定は subagent / Skill / メイン会話 / フォーク / Agent Teams / `/btw` の 6 選択肢から、最初に該当した選択肢を採用する

## §3. 用語定義

| 用語 | 定義 |
|---|---|
| サブエージェント | 独立 context で動作し、概要のみ親会話に返却する委譲先（`.claude/agents/<name>.md`） |
| 自動委譲 | description のトリガー条件に基づき Claude が自律的に subagent を呼び出すこと |
| 最小権限の原則 | `tools` フィールドで必要ツールのみを列挙し、暗黙の全継承を回避する設計方針 |
| ネスト不可 | サブエージェントが他のサブエージェントを生成できない公式制約 |
| 委譲先選定 | タスクを subagent / Skill / メイン会話 / フォーク（`/fork`）/ Agent Teams / `/btw` のどれに割り当てるかの判定 |
| プロジェクト規約 | 公式仕様外でプロジェクト内合意済みのルール（references/project-conventions.md 参照） |

## §4. 強制ルール

| ルール | 内容 |
|---|---|
| 改変禁止 | 指示以外の改変は絶対に禁止する |
| 主観禁止 | 「良いエージェント」等の感想・印象の出力は絶対に禁止する |
| 公式仕様外フィールド禁止 | frontmatter に references/official-spec.md §A.1 で未定義のキーを追加しない |
| 推測値禁止 | 不明な値は TBD として明示し、確認すべき情報源を示す |
| 曖昧表現禁止 | references/review-observations.md 観点 9 の禁止語リストに準拠する |
| 根拠必須 | すべての指摘に「公式仕様のどこ」「プロジェクト規約のどこ」を併記する |
| 仮説明示 | プロジェクト推奨は「（推奨／仮説）」と注記する |
| 修正案必須 | 指摘するだけでなく、修正後の具体的記述を提示する |
| 出典 URL 表記 | 公式仕様引用時は `https://code.claude.com/docs/...` の章名を併記する |
| 保存先固定 | 生成した subagent 定義は `.claude/agents/<name>.md` または `~/.claude/agents/<name>.md` に保存する |

## §5. 実行プロセス

### step S-1: モード判定

- **判定基準**：ユーザー入力が以下のいずれに該当するかを 1 回だけ分類する
  - [A] 新規作成：「サブエージェントを作って」「定義したい」等の新規定義要求
  - [B] 既存レビュー：YAML frontmatter + 本文を含む subagent 定義ファイルが入力された
  - [C] 委譲先選定：「subagent / skill / メイン会話のどれが妥当か」を問う質問
- **アンチパターン**：判定不能のまま [A] に進む。判定不能なら「[A]/[B]/[C] のどれか」をユーザーに確認する

### step S-2: [A] 新規作成 — 委譲先妥当性確認（A-0 相当）

- **判定基準**：以下の 6 代替案のいずれかに該当する場合は subagent を作成せず代替案を提示する
  - 1 セッションで 1 回しか使わない → メイン会話で実行（公式：頻繁な往復・反復改善はメイン会話）
  - 単純な再利用ワークフロー → Skill（skill-designer スキルへ）
  - 並列・長時間継続実行 → Agent Teams（公式：subagent は単一セッション内）
  - ネスト呼び出し前提 → Skill またはチェーン（references/official-spec.md §A.5 ネスト不可）
  - 親履歴を継承して並行作業 → フォーク（`/fork`）
  - 既出情報への単純質問 → `/btw`
- **アンチパターン**：上記 1 件でも該当するのに subagent 化する（公式仕様の典型誤用）

### step S-3: [A] 新規作成 — 必須情報の収集（A-1 相当）

- **判定基準**：公式仕様で必須の `name` `description` が確定しているか
  - `name`：小文字・ハイフンのみの一意識別子。references/official-spec.md §A.4 組み込み subagent およびプロジェクト規約 §B.1 既存命名と非衝突
  - `description`：step S-5 のテンプレートに従い動詞ベースで記述
- **アンチパターン**：必須項目未確定のまま生成する。未確定なら一度に最大 3 項目までユーザーに質問する

### step S-4: [A] 新規作成 — 任意情報の決定（A-2 相当・決定強制）

- **判定基準**：references/official-spec.md §A.1 の 14 任意フィールドそれぞれについて「指定する／省略する」を決定する。省略時は理由（公式デフォルトで十分・該当しない等）を記録する
- **出力先**：output.md §A 表「4. 任意フィールド決定記録」
- **アンチパターン**：「とりあえず継承」「とりあえずデフォルト」と未決定で進める。最小権限違反・コスト過剰の温床

### step S-5: [A] 新規作成 — description テンプレート適用（A-3 相当）

- **判定基準**：`description` が以下構造を満たすか
  - 1 文目：このサブエージェントの役割
  - 2〜N 行目：動詞ベースのトリガー条件列挙
  - 末尾：「使用しないケース：…」の除外条件
  - プロアクティブ起動意図がある場合は冒頭 `PROACTIVELY`（プロジェクト規約 §B.3）
- **アンチパターン**：1 文だけ・名詞句のみで終える。Claude が委譲判断不能になる

### step S-6: [A] 新規作成 — 設計検証チェック（A-4 相当）

- **判定基準**：references/review-observations.md の 11 観点をすべて適用し、1 件でも不合格なら修正してから次 step へ進む
- **アンチパターン**：チェック未完了のまま step S-7 ファイル生成へ進む

### step S-7: [A] 新規作成 — ファイル生成・保存・報告（A-5 相当）

- **判定基準**：保存先パスが references/official-spec.md §A.2 と整合するか
  - ユーザー配布 → `~/.claude/agents/<name>.md`
  - プロジェクト共有 → `.claude/agents/<name>.md`
  - 組織配布 → 管理設定の `.claude/agents/`
  - 既存ファイル存在時は上書き前にユーザー確認を取る
- **出力先**：output.md §A 新規作成結果テンプレート全章
- **アンチパターン**：上書き確認なくファイルを破壊する

### step S-8: [B] 既存レビュー — 11 観点必須適用

- **判定基準**：references/review-observations.md の観点 1〜11 すべてを評価する。問題のない観点も「✅ 問題なし：[根拠]」として明示する
- **出力先**：output.md §B レビュー結果テンプレート（深刻度ラベル 🔴 CRITICAL / 🟡 WARNING / 🔵 INFO 方式、プロジェクト規約 §B.4）
- **アンチパターン**：観点 1〜11 のうち一部のみ評価して報告する（適用漏れは観点 9「曖昧表現」「主観混入」と同等の品質欠陥）

### step S-9: [C] 委譲先選定 — 判定フロー適用

- **判定基準**：以下の 6 段階フローを順に評価し、最初に該当した選択肢を採用する
  1. 既出情報への単純質問 → `/btw`
  2. メイン会話履歴をそのまま継承して並行作業 → フォーク（`/fork`）
  3. 並列・持続実行・context window 超過の可能性 → Agent Teams
  4. メイン会話 context を保ちつつ再利用ワークフロー → Skill
  5. 大量出力・専用権限・概要のみ返却で十分 → サブエージェント
  6. 頻繁な往復・短いタスク・即応性重視 → メイン会話
- **出力先**：output.md §C 委譲先選定結果テンプレート
- **アンチパターン**：フロー順序を入れ替えて評価する。判定結果が変わる

## §6. 結果出力

`${CLAUDE_SKILL_DIR}/output.md` に記載されたテンプレート構造に従って出力する：

- §A 新規作成結果テンプレート（モード [A] 採用時）
- §B レビュー結果テンプレート（モード [B] 採用時、深刻度ラベル方式）
- §C 委譲先選定結果テンプレート（モード [C] 採用時）
- §X 異常時中断報告テンプレート（判定基準 3 回連続未充足時）

異常時中断報告に含める項目：

- 中断 step 番号 / step タイトル
- 不充足だった完了判定項目
- 再試行履歴（最大 3 回分）
- ユーザー判断要否を含む次アクション
