# ステップ詳細化要素（推奨／仮説・選択適用）

§{連番} 実行プロセスの各ステップに付随させる以下 3 要素は、**適用条件に該当する場合のみ追加** する。
全要素一律適用は不要。該当しない要素を無理に埋めない。

| 要素 | Tier | 内容 | 適用条件 |
|------|------|------|----------|
| **判定基準** | T1 | 「どう決めるか」の認知手順を 1 行で示す | ステップに判断要素がある場合（≒ ほぼ全ステップ） |
| **出力先** | T1 | output.md のどの章・列にマッピングするか | スキルが外部出力テンプレート（`${CLAUDE_SKILL_DIR}/output.md` 等）を持つ場合 |
| **アンチパターン** | T2 | 既知の典型ミス・落とし穴を 1 行で示す | ドメインに既知失敗パターンが蓄積されている場合 |
| **手順** | T3 | 順序付きサブ操作系列を示す | ステップが順序付きサブ操作に分解可能 AND 順序が意味を持つ AND **判定基準併記必須** AND **思考代替防御セット D1/D6/D10 必須**（後述） |

T1+T2 はプロジェクト規約 B.6 由来、T3 はプロジェクト規約 B.7 由来の推奨追加要素（推奨／仮説）。
既存の豊富プロトコル（例：clean-architecture の「ユーザーからの問い／根拠／手順／出力」）を持つスキルへの T1+T2 重複適用は避ける（4 要素プロトコルは T3 + 判定基準層を内包）。

## ステップ記述形式

**最小形式**（詳細化要素なし）：

```
### step S-{連番}: {タイトル}
```

**詳細化形式**（要素適用時、適用条件を満たす要素のみ記述）：

```
### step S-{連番}: {タイトル}
- **判定基準**：{基準}
- **出力先**：output.md §{章番号}（{章名}）
- **アンチパターン**：{禁止事項}
```

最小形式 / 詳細化形式は同一スキル内で混在可能。スキル特性に応じて要素を選択する。

# §0 仮説と事実の区別 章（推奨／仮説・選択適用）

§0 章は **適用条件に該当する場合のみ追加** する。一律適用は不要。

| 適用条件 | 該当例 |
|---------|--------|
| 外部権威からの引用と実務派生の推奨が混在する | clean-architecture / coding 系 / security |
| 主張の出所種別が複数ある | system-design / spec-driven-development / skill-designer |
| 「（推奨／仮説）」マーキングが本文に頻出する | clean-architecture / coding 系 |

不適用例：機械的処理中心スキル（update-config 等）への適用は形骸化リスクのため避ける。

## §0 の機能

§0 は **AI 生成のエピステミック契約を本文冒頭でコンテキスト注入する装置** として機能する。Claude Code 公式仕様「スキル呼び出し時に SKILL.md 本体は会話に 1 メッセージとして注入され、セッション残りで持続する」と整合し、本文を生成する AI が後続セクションで主張を区分マーカー付きで一貫記述するための self-binding contract を冒頭で確立する。

## §0 設置時の遵守事項

- 4 区分（公式仕様 / プロジェクト規約 / 推奨（仮説） / 不明）を明示する。スキル特性に応じて区分名・粒度を調整可（例：clean-architecture は「Martin 原典 / プロジェクト規約 / 実装上の選択」の 3 区分）
- §0 で宣言した区分マーカー（「（推奨／仮説）」「プロジェクト規約より」「TBD」等）を本文中で一貫して適用する
- §0 のみで誤読防御は完成しない。**§0 + 本文中の個別マーキング** の両方が揃って初めて防御が機能する

# 手順 T3 採用時の思考代替リスク防御（推奨／仮説）

手順 T3 を採用するスキルは、思考代替リスク（AI が手順を機械的に踏襲し判断を放棄する失敗モード）を構造的に防ぐため、以下 3 防御を **必須セット** として併設する。

## T3 該当範囲（適用範囲の限定）

T3 は **§5 実行プロセス章または同等の中核フロー章に配置され、スキル本体の主目的を達成するための中核フロー** を構成する手順のみを対象とする。以下は T3 対象外であり、防御セット併設は不要：

- 異常時例外回復手順・フォールバック条件分岐
- 前提条件確認手順・初期化手順
- 出力フォーマットの記述順序

「順序付き手順がある = T3」ではない。

## 失敗モード

| # | 失敗モード | 症状 |
|---|----------|------|
| F1 | 機械的踏襲 | 入力特性を無視して (1)→(2)→(3) を全件実行 |
| F2 | 目的盲目 | 手順は完遂するが目的を達成しない |
| F3 | 矛盾耐性喪失 | 入力が手順前提と矛盾しても踏襲継続 |
| F4 | 冗長模倣 | 手順を逐語的に出力にコピー |
| F5 | 逸脱拒否 | 文脈が逸脱を要求しても手順に固執 |

## 防御セット

| 防御 | 配置 | 内容 | 主な対象失敗モード |
|------|------|------|-----------------|
| **D1 原理ラッピング** | §5 intro / 各 step | 手順は判定基準と必ず併記。手順単独記述を禁止 | F1 |
| **D6 完了判定ゲート** | §5 末尾 | 手順完了後に判定基準充足を検証。手順遵守 ≠ ステップ完了 | F2 |
| **D10 メタルール** | §4 強制ルール | 「思考代替防止」「判定基準優先」2 ルール追加 | F3 / F5 |

## 適用条件

- 手順 T3 を採用するスキルでは、防御 3 層を **必須セット** として併設する
- 手順 T3 を採用しないスキルでは、防御セットも不要
- 既存豊富プロトコル保有スキル（clean-architecture 等）は 4 要素プロトコル内で T3 + 判定基準層を内包しているため、§0 / T1+T2 とは別途防御セット併設が必要

## D1 / D6 / D10 の具体例

### D1 原理ラッピング（§5 intro 注記例）

```
4 要素プロトコルにおいて「ユーザーからの問い」と「根拠」は判定基準層を構成し、「手順」を原理的に拘束する（思考代替リスク防御 D1）。手順単独の記述は §4「思考代替防止」ルールで禁止される。
```

### D6 完了判定ゲート（§5 末尾サブセクション例）

```
### ステップ完了判定（思考代替リスク防御 D6）

各 step の「手順」完了後、以下を検証してから次の step に進む：
- [ ] 判定基準（問い・根拠）への回答が出力に含まれているか
- [ ] 入力前提と矛盾する結果が出ていないか
- [ ] 出力が次 step の入力として整合するか

充足しない場合：手順を機械的に再実行せず、判定基準に立ち返り別経路を検討。
最大 3 回再試行、3 回失敗時は §6 異常時出力で中断報告する。
```

### D10 メタルール（§4 強制ルール例）

```
| 思考代替防止 | 各 step の「手順」は必ず「判定基準」と併記する。手順単独記述を禁止する（D1）|
| 判定基準優先 | 各 step で「手順」と「判定基準」が衝突した場合は判定基準を優先する。手順への機械的従属を禁止する（D10）|
```

詳細は skill-designer/SKILL.md 付録 B.7「手順 T3 + 思考代替リスク防御セット」を参照。
