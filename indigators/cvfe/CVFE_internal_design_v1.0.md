## 0. 本書の位置づけと非目標

本書は仕様書 §3〜§6 を、`indigators/` 配下の既存指標パッケージ規約（`src/` 純粋ロジック層
＋ `tests/` ＋ `conftest.py`）へ写像するための内部設計である。

**本書は仕様を変更しない。** 仕様に既定値が置かれている項目（TSRV の `K = ceil(n^(2/3))`、
`freeze_thresh = 0.05`、`RRANGE` の `m = 12`、`refit_every = 0`）は既定値のまま実装する。
仕様 §10 の TBD-1〜7 はいずれも**検証段階（§9 段階 3 以降）で決定する項目**であり、
実装をブロックしない。TBD-7（適用時間足）は `bar_edges` / `bar_interval_sec` を入力
パラメータとしているため実装へ焼き込まれない。

**非目標**：仕様 §9 段階 3〜8（実データ検証・事前登録・検出力計算・OOS・下流影響）は
研究検証プログラムであり、本書の対象は段階 1〜2 が要求する実装と、段階 3 以降を
実行するために必要な計算基盤（§5 評価手続き）までとする。

**依存方向の規則**

1. 矢印は上から下への一方向のみ。下位が上位を import しない。
2. `evaluation.py` は `engine.py` に依存しない（評価は「予測系列 → 損失」の純関数であり、
   予測の生成手段を知る必要がない ＝ M0〜M4 を同一の面で比較できる）。
3. 外部依存は `numpy` のみ（仕様 §6）。`math` は標準ライブラリのため許容し、
   `Γ`（`math.gamma`）と `erf` の供給に用いる。`scipy` / `pandas` は使用しない。
4. `Φ^{-1}` は既存共有プリミティブ `common.normal_dist.norm_ppf`（Acklam 有理近似）を
   **無改変参照**する。定常ブートストラップ（§5.2）は `common.stats_boot.
   stationary_bootstrap_indices`（Politis-Romano 1994）を無改変参照する。
   → 新規の重複実装を持たない（OCP：係数 1 個の訂正が 2 ファイル改変を要求する状態を作らない）。

先回りした抽象化を導入しない（YAGNI）。

## 3. データ構造

### 3.1 `CvfeParams`（frozen dataclass）

仕様 §3.1 の任意パラメータを保持する。生成時に §3.1 の制約を検証し、違反時は
`E05_PARAM_RANGE` を送出する。検証点を 1 箇所に集約し、各段階での再検証を不要にする。

| フィールド | 既定 | 制約（仕様 §3.1） |
|---|---|---|
| `n_har` | 1500 | `≥ 500` |
| `lam_gap` | 0.97 | `0.90 ≤ x < 1.0` |
| `jump_alpha` | 0.999 | `0.99 ≤ x ≤ 0.9999` |
| `freeze_thresh` | 0.05 | **なし**（仕様 §3.1 は値域を規定していないため実装も制約を追加しない） |
| `refit_every` | 0 | `≥ 0` |
| `bar_interval_sec` | （必須） | `≥ 60` |

`ticks` / `bar_edges` の単調性（E02 / E04）は配列の性質であり別コードが割り当てられている
ため、`CvfeParams` ではなく `sampling.py` が検証する（検証点はスカラ制約とは別）。

### 3.2 `BarMeasure`（frozen dataclass・1 バー 1 個）

`engine` と `CvfeSequential` が共有する「1 バーの確定量」。**この型が一括経路と逐次経路の
唯一の接続面**であり、両経路の bit 一致（仕様 §6・§9 段階 1）の構造的根拠となる。

| フィールド | 内容 |
|---|---|
| `n` | バー内サンプリング済み収益の本数 |
| `v` | 測定量 `V_t`（§4.3） |
| `c`, `j`, `jump_flag` | 連続成分・ジャンプ成分・検出フラグ（§4.4） |
| `p_open`, `p_close`, `p_high`, `p_low` | バー内対数価格の始値・終値・高値・安値 |
| `t_first`, `t_last` | バー内の最初・最後のティック時刻（§4.7 のギャップ判定に使用） |
| `valid` | ティック数 `< 2`（`E06`）で `False` |

### 3.3 `CvfeState`（frozen dataclass）

段階 0〜1 と段階 4 学習の成果。逐次経路の初期化に必要十分な情報のみを持つ。

`measure_id` / `delta_star_sec` / `omega2_hat` / `freeze_ratio` / `quality_gate` /
`har_coef (6,)` / `har_resid_var` / `gap_v_init` / `first_available_index`

### 3.4 `CvfeResult`（frozen dataclass・仕様 §3.2 の出力 DTO）

仕様 §3.2 の 12 フィールドを持つ。加えて診断用に `signature_slope`（§4.1-5 の `S`）を
13 番目のフィールドとして保持する（§4.1 の判定根拠を呼び出し側が検証できるようにするため。
仕様 §3.2 には無い**追加出力**であり、既定値を持つため既存の生成箇所を壊さない）。
全 `np.ndarray` に `setflags(write=False)` を適用し、`dataclass(frozen=True)` とする（仕様 §4.8）。

`har_coef` / `har_resid_var` は**最終的に予測へ用いられた**係数を返す。`refit_every = 0`
（既定）では初回学習の値と同一であり、`refit_every > 0` では最後の再学習後の値になる
（仕様 §3.2 はどちらを指すか規定していない）。

## 4. 一括経路と逐次経路の同一性（仕様 §6「Look-ahead 不在」の構造的保証）

仕様 §6 は「一括計算と 1 バーずつの逐次計算の `sigma_hat` が bit 一致」を要求する。
**浮動小数の演算順序が経路で異なれば bit 一致は成立しない。** よって両経路が
「同一の関数を同一の順序で呼ぶ」ことを型で強制する。

```
fit_state(ticks, bar_edges, params) ──▶ CvfeState        # 段階 0・1・4（学習）
measure_bar(bar_ticks, params, state) ─▶ BarMeasure      # 段階 2・3（1 バー純関数）

CvfeSequential(state, params)
    .push(BarMeasure) ─▶ (sigma_hat_t, sigma_oc_t, sigma_co_t, available_t)
                                                         # 段階 4(予測)・5・6・7

compute_cvfe(...) := fit_state ▶ [measure_bar]*N ▶ CvfeSequential.push ×N
```

- 一括経路 `compute_cvfe` は上式の右辺そのものであり、逐次経路と**同一の関数・同一の順序**を
  通る。よって bit 一致は実装の性質ではなく構成の帰結となる。
- 加算順序を変える最適化（`cumsum` による窓和など）は導入しない
  （プロジェクト規約：ベクトル化は bit 一致検証を伴う場合にのみ行う）。
  ベクトル化はバー**内**（`measure_bar` の内部・両経路が共有）に限定する。
- `refit_every > 0` の再学習は `CvfeSequential` の内部状態遷移として実装し、
  一括経路も同じ遷移を通る。

**性能設計**：段階 0（`K = 4.2e7` ティックで p99 < 180 s）は全期間の集約であり
バー単位の逐次性を持たないため、`np.searchsorted` による前値補間で完全ベクトル化する。
段階 2〜7（`N = 5,000` バーで p99 < 60 s）は Python ループ 5,000 回＋バー内ベクトル演算であり、
1 バーあたり 12 ms の予算に対して十分な余裕がある。

## 5. 因果性（look-ahead 不在）の設計上の担保点

仕様 §4 柱書：バー `t` の `σ̂_t` 算出に参照可能なのは `bar_edges[t]` より厳密に前のティックのみ。

| 箇所 | 担保方法 |
|---|---|
| §4.5 学習標本 | `t ∈ [t0 − n_har − 1, t0 − 2]`（`y` の添字が `t0 − 1` を超えない）を索引計算で固定 |
| §4.6 予測 | `ŷ_t` は `x_{t−1}` のみを引数に取る（`x_t` を受け取れない関数シグネチャとする） |
| §4.7 ギャップ | `σ̂_CO,t = sqrt(v_{t−1})`。EWMA 更新は `σ̂_CO,t` を確定した**後**に行う |
| §4.1 診断 | 診断対象は先頭 `n_har` 本に限定（仕様 §4.1-1）。予測対象 `t >= t0 = n_har + 22` と重ならない |
| §4.5-6 再学習 | `CvfeSequential` が `t−1` 以前の履歴のみを保持し、そこから再構成する。`refit_every > 0` でも切詰め不変性が成立することをテストで固定 |
| §4.7 EWMA 初期値 | 仕様通り「先頭 200 本のギャップ保有バー」。当該 200 本目の索引が `first_available_index` 未満であることを検証し、違反時は `WARN` を出力する（診断のみ・仕様は変更しない） |

## 7. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 全段階を 1 ファイル（`cvfe.py`）に集約 | 測定量追加（K4 実現カーネル）が HAR・ギャップと同一ファイルの改変を要求する（OCP 違反） |
| 一括経路をバー横断でベクトル化し、逐次経路を別実装で持つ | 加算順序が分岐し、仕様 §6 の bit 一致が実装依存の偶然になる |
| `Φ^{-1}` / 定常ブートストラップを本パッケージに再実装 | `common/` に既存。複製は ISSUE-179 で是正済みの OCP 違反を再導入する |
| `evaluation.py` を `engine.py` に統合 | M0〜M4 の比較対象は CVFE の出力形式を知らない。統合すると評価が予測実装に結合する |
| 多変量 OLS に `common/ols_fit.py` を再利用 | 同モジュールは設計行列を `Φ = [1, x]` の 2 列に固定しており HAR の 6 係数へ適用できない。同ファイルは「bit 一致が保証境界」と明記しており、一般化は既存 2 呼び出し元の出力を変えうる。`har.ols_with_intercept` にローカル実装し、`common/ols_fit.py` は改変しない |
| Newey–West ラグに `market_profile/analysis/mp_stats/stats_core.py` を再利用 | 同実装は `ceil` 丸めであり仕様 §5.2 の `floor` と一致しない。加えて兄弟具象の analysis 層への側方依存となる。`evaluation.newey_west_lag` にローカル実装する |
| `errors.py` と `logs.py` を `diagnostics.py` へ統合 | `logs.py` は個々のコードを列挙しない（`emit(level, code, ...)` を受け取るだけ）。コード追加は `errors.py` のみの改変で済み、統合の根拠となる「1 変更が 2 ファイルを要求する」状態は生じない |
| `gap_factor = 1.5` を `CvfeParams` へ外出し | 仕様 §3.1 に存在しないパラメータを実装が追加することになる。§9 段階 5 は「パラメータ事前登録」を求めており、実装都合の追加は凍結対象を歪める。`gap.GAP_FACTOR` として 1 モジュールに閉じる形に留める |
